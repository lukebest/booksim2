本次只跑 1 个 plane / 1 条 ring、均匀 tiled 写、 S0 与 S1。每 core 20000 笔 WriteNoSnp （请求量 ×10），每笔 2 个 WriteData flit。 HA 回 RSP / Comp 时延 U{4..64} 拍。

结论

  1. 单平面把注入口砍半。S0 吞吐 2.6707 flit/cycle，max/min 1.0765，重试 0.0027 次/事务， 延迟 p50 = 74166。
  2. S1 相对 S0 吞吐 -0.1%，max/min 1.0765 → 1.0819。
  3. §4.3 上环方向见下。黄底 = CW/CCW 比 ≥ 2 （该侧合计 ≥ 50）。预测写在跑数前，对照见 1.2.1。

1.2 协议：CHI WriteNoSnp 四拍握手

一笔写 = REQ → DBIDResp → WriteData×2 → Comp。 per-core 写带宽 = 争用窗口内成功上环的 WriteData flit / cycle。

1.2.1 写激励

地址走 tile × 64KB + (i mod 16) × 4KB，interleave 已均衡。 completer 侧每条 RSP（DBIDResp / RetryAck / Comp）独立抽 U{4..64} 拍；同一笔事务在 S0 / S1 抽到同一份时延。 本轮 1 plane、K = 20000。

跑数前的预测（置信度 0.55）： 单平面、请求量 ×10、DBIDResp/RetryAck/Comp 各抽 U{4..64} 的均匀 tiled 写：成功上环仍按最短路接近 1:1；失败次数比双平面更偏，邻 mem 少的核失败比 ≥ 2；S1 两边一起限速，改不了方向比，吞吐低于 S0。 证伪：成功比 ≥ 2，或所有核失败比仍 < 2（与双平面一样），或 S1 吞吐不低于 S0
总线时延 30 拍的预测（置信度 0.7）：拥塞总线时延改为 30 拍（控制窗口 64 的一半）后，S1 用的是更旧的拥塞等级；上一轮总线=1 时 S1 已几乎等于 S0，更晚的反馈再拉开吞吐的空间很小。CW/CCW 失败比仍由邻 mem 几何决定，S1 改不了。 证伪：S1 吞吐相对 S0 掉超过 2%，或失败偏的核/方向翻面
对照：S1 总线实测 30 拍。
对照。 8 个 mem 收到的 WriteData 完全一样（50000 / HA）。 S0 延迟 p50 = 74166，max/min = 1.0765。 S1 吞吐 2.6683（-0.1% vs S0 2.6707）。 S0 上环方向高亮 0/10 个核 （成功偏 0，失败偏 0， 失败最大比 1.904）； S1 高亮 0/10 个核 （失败最大比 1.911）。 预测写在 meta.stimulus_forecast，对照写在 meta.belief_update，前者不改。

4.1 先排除“离 mem 更远”

到 8 个 mem 的平均跳数全部等于 5.0。r(带宽, 平均跳数) = 0.0。失衡的来源不是距离。

4.2 真正的判据：紧邻的 mem 有几个

  • C2、C4、C6、C12、C14、C16 两侧都是 mem → 相邻 mem = 2；
  • C0、C8、C10、C18 有一侧是非终端 → 相邻 mem = 1。
带宽与相邻 mem 个数 r = 0.9764 （Spearman 0.8528）。 单平面上这条链没有被 retry 盖住：有限 tracker 几乎不咬 （重试 0.0027 次/事务）。
