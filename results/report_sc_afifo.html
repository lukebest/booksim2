SystemC 周期级跨 Reticle AFIFO 仿真报告 (4×4, reticle=2×2)

拓扑 4×4 mesh，reticle = 象限 = 2×2 (边界 col/row 1|2)。四个 reticle 各一个独立时钟域 (同频, 周期 1ns, 独立静态相位 + 每周期有界相位游走抖动 σ)。跨界链路经 Cummings 型双时钟 Gray 指针 AFIFO (sc/afifo.h)，S 级同步器；读策略对比 greedy(AFIFO 非空即读，可能与下游 本地已调度流量冲突) vs gated(仅当下游节点有空闲输出端口时才读，杜绝冲突但可能增加占用/回压)。 Python 侧仍复用 sim_hamilton_ring / sched_zerobuf_compare 产生的 0-buffer 刚性调度作为全网流量踪迹 (utils/export_sc_trace.py)，SystemC 侧 (sc/mesh_tb.cpp) 做真正周期级、含时钟边沿与同步器移位寄存器的 CDC 重放。

术语说明

S（同步器级数）
Gray 码写/读指针跨时钟域进入对侧时，在目标时钟域需要经过的触发器级数。 本仿真采用 Cummings 型双时钟 AFIFO 模型：写指针经 S 级移位寄存器同步到读域后， 读侧才能"看到"新的写进度，从而判断 FIFO 是否为空；满信号（almost-full）同样经 S 级同步回写域产生反压。工业界常用 S=2（双触发器同步器）。 S 越大，指针可见延迟越长，读侧空/满判断越保守，物理峰值占用通常越高 （读侧更晚才开始排水，写侧在同步窗口内可能多攒 flit）。
σ（sigma，抖动）
每个时钟边沿相对于标称周期的随机相位游走标准差，单位为 UI （Unit Interval，即 1 个时钟周期 = 1 UI）。例如 σ=0.1 表示每周期边沿时刻 约有 10% 周期（RMS）的随机扰动，在 ±0.5 UI 内截断。 各 reticle 时钟同频（mesochronous），但静态相位独立、边沿时刻逐周期随机游走。 抖动会在少数周期翻转写/读边沿的 setup 关系，使有效 CDC 延迟在 S 与 S+1 个读周期之间跳变，从而略微抬高 AFIFO 峰值占用。
总缓存 flits
所有跨 reticle 边界 AFIFO 实例的物理峰值占用之和： Σ peak_phys_occ（单位：flit）。 每条链路的 peak_phys_occ 是该 AFIFO 在整个 allgather 过程中， 存储阵列中同时存在的最大 flit 数（wptr − rptr，不含同步器可见性延迟）。 这是跨 die/reticle 边界缓冲区的容量规划数：若每条 AFIFO 均按各自峰值深度配置， 总 SRAM/bit 成本 = 总缓存 flits × flit 位宽（本报告未乘位宽，仅统计 flit 数）。 表中 "mean" 列为 Monte Carlo 多种子（随机相位）下的平均值。
peak_occ vs peak_phys_occ
peak_phys_occ：真实存储占用（硬件必须实现的深度）。 peak_occ（可见占用）：读侧经 S 级同步器"看到"的写指针 与读指针之差，用于 FIFO 内部空/满逻辑，通常比物理占用低 0–S 个 flit。 容量规划应使用 peak_phys_occ。

波形查看 (gtkwave)

仿真支持 VCD 波形 dump，可用 gtkwave 打开查看各 AFIFO 占用、读写握手与域内周期计数。

cd sc
make
./mesh_tb --trace ../results/sc_trace_ring_4x4.trace \
  --scheme ring --policy gated --sigma 0.1 --sync 2 --depth 4 --seed 1 \
  --vcd ../results/sc_afifo_wave_ring
gtkwave ../results/sc_afifo_wave_ring.vcd

信号命名：dom<d>_cyc = reticle d 的本地周期计数； x<i>_p<src>_c<dst>_wr_* = 第 i 条跨界 AFIFO 写侧（写域时钟边沿更新）； _rd_* = 读侧（读域时钟边沿更新）。重点信号： wr_occ_phys / rd_occ_phys = 物理占用； rd_occ_vis = 经 S 级同步后读侧可见占用； wr_stall = 写侧因 FIFO 满而反压； slot_free = gated 策略下该周期下游是否有空闲输出端口。

验证

1. 质量守恒 (writes == reads)

通过：sc_afifo_sweep.py 的 required_depth_probe 对每条跨界链路均断言 write_count==read_count（否则会抛出异常终止），本次完整扫描全部通过。

2. gated 策略下游冲突恒为 0（不变式）

通过：在完整扫描 (2 方案 × 2 sync × 4 sigma × 8 depth × 20 seeds) 中，gated 策略的 collisions 全部为 0，符合设计（仅在下游有空闲输出端口时才读出 AFIFO）。

结论

  • 4×4 规模下两方案的 AFIFO 所需深度都很小 (p95 ≤ 2 flit)，σ=0.1 时总缓存开销 全局环 ≈12 flits，hybrid vband ≈24 flits（hybrid 跨界链路数更多: 16 vs 12）。
  • gated 策略以设计不变式的方式 杜绝了下游冲突 (collisions 恒为 0)，代价是在深度不足时 (depth=1) 与 greedy 产生几乎相同的 writer stall —— 即在此规模下 gated 并未显著增加所需深度， 是相对"免费"的安全策略。
  • greedy 策略在 ring 方案上观测到少量下游冲突 (σ=0.1, S=2 时 5~12 次，随机种子/S 而变)， 在 hybrid 方案上该规模下未观测到冲突 —— 说明 ring 的跨界目的节点输出端口更容易与本地环调度 "撞车"，hybrid 的树形分叉在跨界节点上余量更大。是否需要 slot-gated 读取取决于目标路由器能否 承受这类偶发的额外输入压力；由于 gated 在本研究规模下几乎不增加深度/延迟成本，建议默认采用 slot-gated 读取策略。
