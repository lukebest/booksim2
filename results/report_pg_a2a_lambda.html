10.1.1 缓冲深度：4 个 mesh 端口 + 1 个 ramp 端口（不是 5 个一样深）

旧模型写成「5 端口 × VC × Q」，把下 ramp 的本地端口也按 Q=19 计，这是错的。输入缓冲的深度只由喂给它的那条通道的 credit 回环 决定：上游 t 拍发出 → t+L 落地 → 最快 t+L 走 → credit 在 t+2L 回到上游， 所以要让这条链路每拍都能发，深度需要 2L+1。四个 mesh 端口各自挂在一条 router→router 链路上，本地端口挂的却是同一个 tile 内的 NI ramp，根本不在 credit 回环里——放不下的 flit 只是继续待在 NI 自己的队列里，不会卡住任何链路。

E / W（2 个）横向链路7 1519 吞吐只要 2H+1=15，但实测尾时延变差，故与 N/S 取齐
本地（1 个，上 ramp）同 tile 的 NI ramp ——3 不在 credit 回环里：RAMP_BW=2 一拍的突发 + 1 个流水槽
下 ramp（弹出）——— 0 弹出的 flit 直接从 mesh 输入端口以 2 flit/cy 出网， 不再单独排一级缓冲

10.1.2 源路由头 28 bit / 29 bit 是怎么来的

源路由 = 不查表：源节点把整条路径压进包头， 每个 router 只做「弹出头部 2 bit → 照它转发 → 跳数减一」。 所以头的宽度由最长路径决定，而不是由节点数决定。 公式 ceil(log2(H_max+1)) + 2*H_max + [1 bit VC]。

字段bit为什么是这么多
hop_count4要能表示「还剩 0…12 跳」共 13 个取值，⌈log₂13⌉ = 4 bit
dir[12]24每跳 1 个 2 bit 方向码（E/W/N/S），按最坏路径 Hmax = 12 跳开定长字段：2×12
vc_sel0只有 1 条 VC，无需选择位
健康 XY 合计28 1 VC，无 VC 选择位
Super-turn 合计29 同样的路径、同样的 Hmax，只多 1 bit vc_sel（硅上 2 层 Glass–Ni，包在源端锁定一层）

三个关键点：
① 每跳 2 bit：一个 router 的可选输出只有 E/W/N/S 四个方向， 2 bit 正好编码；「弹出」不用编码，跳数减到 0 就是到站。
② 为什么是 Hmax=12 而不是平均跳数：头是定长字段， 必须按最坏路径开宽度。健康 8×6 的曼哈顿直径 = (8−1)+(6−1) = 12， 所以 2×12 = 24 bit 的方向串。
③ hop_count 4 bit：要能表示 0…12 共 13 个取值，⌈log₂13⌉ = 4 bit。 没有它，router 无法区分「方向串还剩几个有效」和「后面是填充位」。

开销占比：28 / 512 bit flit = 5.47% （Super-turn 29 / 512 = 5.66%）。两者都塞得进同一个 flit 的头部， 不额外产生一个 flit，所以源路由在本设计里不增加线上流量—— 它换掉的是每个 router 里的路由表。

10.1.3 目的路由表 94 bit 是怎么来的

这是每个 router 一份的表，回答的问题只有一个： 「包要去 d，我该往哪个方向送？」公式 (A-1) * 2 bit = 47×2 = 94 bit。

项值为什么
表项数47 每个其它存活节点一行：A−1 = 48−1 = 47。 「目的就是我」那一行不用存，它是弹出，由 dest == my_id 直接判出
每项宽度2 bit 一行只需要说出一个输出方向：mesh 只有 E/W/N/S 四个， 2 bit 正好编完
目的 id 本身0 bit 表是用目的 id 直接索引的（第 d 行就是去 d）， 不是 CAM，所以行里不存 key
VC 字段0 bit Super-turn 虽然按 2 VC 计缓冲，但那一层是源端选定、随包携带的， 路由器不需要为它再存一位，所以 2 VC 下每行仍是 2 bit
合计94 bit ≈ 11.8 B，比一个 flit（512 bit）还小

和源路由的分工：目的表把 94 bit 压在每个 router 里 （全网 48 个 router 共 4512 bit ≈ 0.6 KiB）， 换来包头 0 bit；源路由反过来，router 里 0 bit，包头 28 bit。

什么时候目的表不够用。只按目的查表的前提是 「同一个 router 上，去同一个 d 的所有包下一跳唯一」。健康 XY 满足 （冲突数 0）。故障残图上 Super-turn 常常不满足： 同一个 (router, d) 会因为来源不同而必须走不同方向，才能既绕开故障 又不违反转向模型。本目录 14 个故障场景里只有 1 个仍然 dest-only 可行；其余要么升级成 源感知表（键变成 (src,dst)，见 10.1 表里的「源感知表 bit（最大）」）， 要么退回源路由（每 router 0 bit，代价是包头那 29 bit）。
