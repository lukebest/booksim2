6×8 2D Mesh Allgather 三方案分析

Mesh 6×8（N=48），H=4 cy，V=6 cy，上/下 ramp 各 1 cy，下环带宽 ramp_bw ∈ {1, 2} flit/cy/节点，数据量 m ∈ {1..5} flit/节点。

物理模型与 Buffer 定义

  • 刚性 0-buffer 打包器（sched_zerobuf_compare.py）：每个源分配唯一注入偏移，任意时刻每条有向链路 / 上环 / 下环最多被一个 flit 占用——by construction 零 router/link/ramp 排队。本报告 makespan 优先采用此数据。
  • 事件驱动仿真（allgather_fast_sim.py）：贪心“链路一空就发”，makespan 更低但可能需排队；仅作 rigid pack 失败时的回退参考。
  • 节点 SRAM（row→col 独有）：行相结束后须本地攒够 (MX−1)×m flit 再做列相。
理论下界 T = max(弹出下界, 角节点下界, 延迟下界, 二分带宽下界)；6×8 在 m=1,ramp_bw=1 时 T=64 cy（角节点下界紧）。

Makespan / Buffer 来自 sched_zerobuf_compare.py 刚性 0-buffer 打包器（pack 成功则 by construction router/link/ramp 零排队）；pack 失败格回退 ED 并标黄。 BookSim Route B 仅覆盖 rigid 0-buffer 格。

方案二：ring_uni / ring_bi / hybrid_v_bi_B2

  • ring_uni：任意 m 均有 rigid 0-buffer 调度（如 m=5@rb=1：rigid mk=309 vs ED 贪心 mk=274+link wait）。

方案三：先 Row Allgather，后 Column Allgather

算法

  1. 行相：每行独立 allgather（6 节点），各节点获得整行 6m flit。
  2. 列相：每列独立 allgather，转发整行包（6m flit/次注入），完成后每节点持有 48m flit。

Buffer 诉求（两层）

  • 网络内（router/link）：严格 0 buffer，对任意 m 成立——1D fork 结构 + 刚性偏移在 6×1 / 1×8 虚拟网格上天然无重叠。
  • 节点 SRAM：(MX−1)×m = 5m flit/节点——第二阶段须等整行到齐、本地落地后再二次上环；tree/ring/hybrid 全程直通转发，无此暂存。
