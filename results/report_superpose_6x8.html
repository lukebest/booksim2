6×8 Mesh：Allgather ⊕ Broadcast / Gather 零缓冲叠加分析

Mesh 6×8 · H=7 · V=9 · ramp_bw=1 · root=[0, 1] · 刚性足迹打包（无阻塞 / 无 router buffer / 无链路冲突）

在第一列节点 (0,1) 上叠加 broadcast 或 gather 与全网 allgather。 使用与 sched_zerobuf_compare 相同的刚性 0-buffer 模型： 每条有向链路 ≤1 flit/周期，ramp ≤ ramp_bw；唯一自由度是注入偏移。

  • AG⊕Bcast：allgather 的 N 个源足迹 + root 的一棵广播树足迹，联合打包。
  • AG⊕Gather：allgather 足迹 + (N−1) 条向 root 的单播 gather 足迹，联合打包。
  • 搜索空间：AG 方案 {multitree, axis_ccw, ring_bi, hybrid_v_bi_B2, border_bi_Q4} × 树形态 {multitree, axis_ccw, yx_tree} × 源顺序 × 交织/串行。

理论下界

AG LB = max(eject, corner, latency, bisect)
Bcast LB ≈ RAMP + max_manh(root,·) + (m−1) + RAMP
Gather LB = max(⌈(N−1)m / ramp⌉, latency_to_root)
AG⊕Bcast LB ≥ max(AG_LB, Bcast_LB, ⌈N·m / ramp⌉non-root down, ⌈2m / ramp⌉root up)
AG⊕Gather LB ≥ max(AG_LB, Gather_LB, ⌈2(N−1)m / ramp⌉root down)  — root 同时要收 AG 的 (N−1)m 与 gather 的 (N−1)m

若最优 makespan = 联合 LB → 完美叠加（free overlap）； 否则 gap 量化叠加代价。串行单独之和是平凡上界。

结论

  • 可叠加性
    两组组合均存在满足零缓冲 / 无冲突 / 无阻塞的刚性方案 （打包器构造保证）。问题不是“能否叠加”，而是叠加后相对联合下界与 单独之和的代价。
  • AG ⊕ Broadcast
    m=1 时 broadcast 可完全藏进 multitree AG 窗口（makespan 甚至略优于 单独 AG，因 greedy 注入顺序被 bcast 扰动后更优）。m≥3 时最优常退化为 串行（ring_bi AG + bcast），交织无法再压缩。
  • AG ⊕ Gather
    m=1 时 gather 亦可完全藏进 AG（makespan=单独 AG=170）。 根节点 down-ramp 硬下界为 2(N−1)m = 94m；m=1 时 AG 窗口（170） 仍有松弛故可 free-overlap。m≥3 时最优多为串行，因 ring_bi AG 已较紧， gather 的额外 (N−1)m root eject 无法再藏。
  • m=1 AG⊕Bcast: makespan=167 ≤ 单独 AG(170) — broadcast 完全藏进 AG 窗口（相对单独之和节省 94）。方案 multitree/multitree (interleave · corner/bcast_first).
  • m=1 AG⊕Gather: makespan=170 = 单独 AG — gather 完全藏进 AG 窗口（root down 硬下界 94 仍有松弛）。方案 multitree/multitree.
  • m=2 AG⊕Bcast: makespan=267, LB=101, 相对 AG +52, 相对单独之和节省 40; 方案 multitree/multitree (interleave).
  • m=2 AG⊕Gather: makespan=310, LB=188 (含 root down ≥188), 相对 AG +95, 相对单独之和节省 9; 方案 multitree/multitree (interleave).
  • m=3 AG⊕Bcast: makespan=310, LB=144, 相对 AG +93, 相对单独之和节省 0; 方案 best_solo/best_solo (ag_first).
  • m=3 AG⊕Gather: makespan=368, LB=282 (含 root down ≥282), 相对 AG +151, 相对单独之和节省 0; 方案 best_solo/best_solo (ag_first).
  • m=4 AG⊕Bcast: makespan=524, LB=192, 相对 AG +94, 相对单独之和节省 0; 方案 best_solo/best_solo (ag_first).
  • m=4 AG⊕Gather: makespan=628, LB=376 (含 root down ≥376), 相对 AG +198, 相对单独之和节省 0; 方案 best_solo/best_solo (ag_first).
  • m=5 AG⊕Bcast: makespan=708, LB=240, 相对 AG +55, 相对单独之和节省 40; 方案 multitree/multitree (interleave).
  • m=5 AG⊕Gather: makespan=898, LB=470 (含 root down ≥470), 相对 AG +245, 相对单独之和节省 0; 方案 best_solo/best_solo (ag_first).

验证

  • 链路占用 ≤1 / 周期；up/down ramp ≤ ramp_bw。
  • AG⊕Bcast：每个非 root 节点 eject = (N−1)m + m；root eject = (N−1)m。
  • AG⊕Gather：root eject = 2(N−1)m；其他节点 eject = (N−1)m。
