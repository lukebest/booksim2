3D 堆叠 NoC：按 top die 分组的写带宽

六个 top die 各是现有的 20 节点双向 full ring × 2 plane （逐边 hop 时延与单环报告相同；原 memory 节点改为 D2D bridge； 数据通路 knobs 与现有 top die 对齐：12+8 上环队列、per-dir/per-vc 端口、 two-write leave、I-tag reserve）。 一个 bottom die：96 个 HA、6 横 + 8 纵 full ring， 横环 4 cycle / 纵环 6 cycle / 挂接点转向 5 cycle。 D2D landing 在 bottom die 上有两个独立接口（接横环、接所在列纵环）， 并用 HPCA'22 SWAP 与有界落地 buffer 解交叉死锁。 带宽口径为瞬时带宽，写带宽单位为 flit/cycle。 workload：burst 128 B、stride 4096 B、 tiling_size 64 KB × 4 tile / core （每核写+读共 4096 笔，同一地址 1:1 WriteNoSnp / ReadNoSnp， 共 245,760 笔）。 地址按 128 B 交织到 96 个 HA，每核覆盖全部 HA （每核打到同一 HA 的次数 42–44）。 每 core outstanding = 128。 每个 HA 跟踪表 512 项，满了走请求 retry （RetryAck → PCrdGrant → 重发 REQ），不是源端控速。

S0 没有源端流控——只要 outstanding 有空位、ring 上有 slot 就发。 S1 再加 AIMD 源端控速。HA 跟踪表满触发的是 CHI 请求 retry，不是源端控速。

结论

  1. outstanding 设为 128。 无拥塞的 WriteNoSnp 往返 = REQ 去程 + DBID 回程 + WriteData 去程 （4 flit 流水，最后一拍比第一拍晚 3 cycle）+ Comp 回程。 最坏一对 (core 4, HA 238) 的去程 100 cycle、回程 105 cycle，合计 413 cycle。额度从 REQ 上环一直占到 Comp 回来。 窗口 128 小于最长 RTT 413，长路径上 core 会先把 128 个槽占满再等 Comp。 本批次每 core 4096 笔，大于窗口 128，实测峰值占用 128，outstanding 上限已经打满——S0 能发出去的条件只剩 outstanding 空位和 ring slot。
  2. HA 跟踪表满是请求 retry 机制。S0 不另加源端控速，S1 才控速。 每个 HA 同时只能收 512 个请求；再来的 REQ 走 RetryAck → PCrdGrant → 重发 REQ，占真实 RSP/REQ 带宽。 S0 完成 4,012/245,760，makespan 663,434 cycle， RetryAck 0 次，有效并发是名义值的 100.0%； S1 完成 4,971/245,760，658,942 cycle， retry 0。 S1 的组写带宽在 t≈3,100 cycle 掉到接近 0（峰值 27.3100 flit/cycle @ t=700），之后 6558 个滑窗没有 WriteData 上环，停滞检测在 658,942 cycle 切断。 根因见第 2.3 节。
  3. 全程完成量均衡，瞬时不均衡。瞬时均衡度用 E[CoVt]。 六个 die 写完同样多的 flit，Jain(E[x]) = 1.00，完成量 max/min = 1.00。 每个 100-cycle 窗上再算六个 group 写带宽的变异系数 (σ/μ)，竞争窗口内 S0 的 E[CoVt] = 0.1465， S1 为 0.1413 （约 22.2% 的窗 CoV > 0.20）。 越低越均，0 表示该窗六个 group 写带宽相同。 均衡流量下理想每组写带宽是 2.631 flit/cycle （总 WriteData / 综合下界 / 6；下界 62,272 cycle， 由纵环切割决定）。S0 全程平均每组 0.0012， 约是理想的 0.0%。 虚线画在组写带宽曲线上。
  4. 对分 / 环带宽按瞬时口径看。 S0：top die REQ 瞬时 85.0%（接近打满）；D2D 对分 DAT 瞬时 52.1%（未打满）；横环 DAT 瞬时 100.0%（打满）；纵环 DAT 瞬时 91.7%（打满）。 S1：top die REQ 瞬时 83.5%（接近打满）；D2D 对分 DAT 瞬时 56.2%（未打满）；横环 DAT 瞬时 100.0%（打满）；纵环 DAT 瞬时 89.2%（接近打满）。 “打满”看最忙那条 CHI VC 的瞬时峰值是否达到该织物有向边数； 全程平均会把排空尾部算进去，会低估峰值占用。 D2D 对分是 48 对双向 SerDes；bottom 落地后横口、纵口可同时上环。
  5. S1 崩溃是纵环 RSP + retry 环被掐断，不是 AIMD 把源端刹死。 S1 的组写带宽在 t≈3,100 cycle 掉到接近 0（峰值 27.3100 flit/cycle @ t=700），之后 6558 个滑窗没有 WriteData 上环，停滞检测在 658,942 cycle 切断。 AIMD 几乎只升窗（617,605 vs 降窗 95）。锁死链：纵环 RSP 打满 → HA 发不出 PCrd/Comp → 0 笔 retry 没有对应重发 → outstanding 挂死 → 写带宽归零。细节在第 2.3 节。

2.3 S1 拥塞崩溃的原因

S1 的组写带宽在 t≈3,100 cycle 掉到接近 0（峰值 27.3100 flit/cycle @ t=700），之后 6558 个滑窗没有 WriteData 上环，停滞检测在 658,942 cycle 切断。 S0 同期峰值 24.6300 flit/cycle（六 die 合计）， 全程平均 0.0086 flit/cycle，并在 663,434 cycle 排空。

  1. 触发点在 bottom 纵环的 RSP，不是 top die，也不是 D2D 对分。 双接口让 D2D 落地可以同时上横环和纵环，纵环 DAT/RSP 瞬时被打满 （S1 纵环 RSP 瞬时 57.6%）。 96 个 HA 的 RSP 上环失败合计 5,868 次，几乎全是 hop_busy / I-tag，说明 HA 要把 RetryAck、PCrdGrant、Comp 送上纵环时，槽已经被在环流量占住。
  2. CHI retry 环被掐断，outstanding 槽回不来。 RetryAck 0 次，但 REQ 只重发了 0 次，差 0 笔： PCrdGrant 发不出（或发在网上走不到 core），core 就一直占着 outstanding。有效并发只剩名义值的 100.0%， 峰值挂起 0 笔。新 REQ 发不出， P-Credit 重发也发不出，写数据在 t≈3,100 之后为 0。
  3. S1 的 AIMD 没有刹住这场风暴。 升窗 617,605 次、降窗只有 95 次，结束时每核预算都顶在窗口 64。 S1 把路径上的拥塞等级从本节点失败里减掉，core 自己上环失败不多， 于是判定“该加窗”；真正挤爆的是 HA 侧 RSP。 scope=core_only 也不限 HA。窗口上限 64 flit / 64 cycle 等于每核最多 1 flit/cycle，反而把写数据变慢，retry 风暴有更长时间 把纵环锁死。S0 没有这个 1 flit/cycle 帽子，在 663,434 cycle 冲完，retry 与重发数量对齐，FIFO 残留 0。
  4. 锁死后出不去。 结束时转向/D2D FIFO 仍坐着 8470 个 flit， 在途 15,279、源端积压 235,070。 FIFO 深度已经顶满（转向 64、D2D 128），偏转把纵环喂饱， HA 更上不去环。连续 655,360 cycle 没有任何 flit 交付，停滞检测判定崩溃——不是“慢”，是死锁。

2.4 拥塞控制：代价–收益 Pareto

下面是此前 1-tile 同构写上的 CC 扫描（不是本页 4-tile / 2-plane 批次）。 目标当时是 E[Jaint] → 1，每组写带宽 → 理想 1.524 flit/cycle。 收益 = √(E[Jaint] × 写带宽/理想)。代价是相对门数 （总线 ≫ HA 状态机 ≫ 每核寄存器 ≫ 每 die 计数器）。 绿点是代价–收益非支配面。扫次 4710.8 s， n_txn=30,720。当前面：S16 HA 授权压低瞬时公平（E[Jaint]=0.7605）且带宽不升；S17 转向让行接近 S1（0.8292 / 58.0%）；S18 RTT 窗 Jain 最高（0.8873）但带宽只有理想的 48.0%；S20 漏桶比周期配额更好（Jain 0.8703，带宽 56.3%）但仍低于 S0；去掉总线的本地 AIMD 掉到 S0 以下（Jain 0.8497，带宽 58.4%）——升窗仍靠路径等级；质量最优仍是 S1 无路径抵消（Jain 0.8742，带宽 62.0%）。非支配面稳定在 S0 无控 / S1 无路径抵消。
