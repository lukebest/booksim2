3D 堆叠 NoC：按 top die 分组的写带宽

六个 top die 各是现有的 20 节点双向 full ring × 2 plane （逐边 hop 时延与单环报告相同；原 memory 节点改为 D2D bridge； 数据通路 knobs 与现有 top die 对齐：12+8 上环队列、per-dir/per-vc 端口、 two-write leave、I-tag reserve）。 一个 bottom die：96 个 HA、6 横 + 8 纵 half ring， 横环 4 cycle / 纵环 6 cycle / 挂接点转向 5 cycle。 D2D landing 在 bottom die 上有两个独立接口（接横环、接所在列纵环）， 并用 HPCA'22 SWAP 与有界落地 buffer 解交叉死锁。 带宽口径为瞬时带宽，写带宽单位为 flit/cycle。 workload：burst 128 B、stride 4096 B、 tiling_size 64 KB × 4 tile / core （每核 2048 笔 WriteNoSnp，共 122,880 笔）。 地址按 128 B 交织到 96 个 HA，每核覆盖全部 HA （每核打到同一 HA 的次数 21–22）。 每 core outstanding = 128。 每个 HA 跟踪表 512 项，满了走请求 retry （RetryAck → PCrdGrant → 重发 REQ），不是源端控速。

S0 没有源端流控——只要 outstanding 有空位、ring 上有 slot 就发。 S1 再加 AIMD 源端控速。HA 跟踪表满触发的是 CHI 请求 retry，不是源端控速。

结论

  1. outstanding 设为 128。 无拥塞的 WriteNoSnp 往返 = REQ 去程 + DBID 回程 + WriteData 去程 （4 flit 流水，最后一拍比第一拍晚 3 cycle）+ Comp 回程。 最坏一对 (core 4, HA 231) 的去程 58 cycle、回程 147 cycle，合计 413 cycle。额度从 REQ 上环一直占到 Comp 回来。 窗口 128 小于最长 RTT 413，长路径上 core 会先把 128 个槽占满再等 Comp。 本批次每 core 2048 笔，大于窗口 128，实测峰值占用 128，outstanding 上限已经打满——S0 能发出去的条件只剩 outstanding 空位和 ring slot。
  2. HA 跟踪表满是请求 retry 机制。S0 不另加源端控速，S1 才控速。 每个 HA 同时只能收 512 个请求；再来的 REQ 走 RetryAck → PCrdGrant → 重发 REQ，占真实 RSP/REQ 带宽。 S0 完成 122,880/122,880，makespan 67,249 cycle， RetryAck 0 次，有效并发是名义值的 100.0%； S1 完成 122,880/122,880，67,871 cycle， retry 0。 两个方案都排空，没有活锁、没有停在停滞检测器上。
  3. 全程完成量均衡，瞬时不均衡。瞬时均衡度用 E[CoVt]。 六个 die 写完同样多的 flit，Jain(E[x]) = 1.00，完成量 max/min = 1.00。 每个 100-cycle 窗上再算六个 group 写带宽的变异系数 (σ/μ)，竞争窗口内 S0 的 E[CoVt] = 0.4205， S1 为 0.4162 （约 95.4% 的窗 CoV > 0.20）。 越低越均，0 表示该窗六个 group 写带宽相同。 均衡流量下理想每组写带宽是 1.524 flit/cycle （总 WriteData / 综合下界 / 6；下界 53,760 cycle， 由纵环切割决定）。S0 全程平均每组 1.2182， 约是理想的 79.9%。 虚线画在组写带宽曲线上。
  4. 对分 / 环带宽按瞬时口径看。 S0：top die REQ 瞬时 90.0%（打满）；D2D 对分 REQ 瞬时 50.0%（未打满）；横环 DAT 瞬时 95.8%（打满）；纵环 REQ 瞬时 86.1%（接近打满）。 S1：top die REQ 瞬时 82.7%（接近打满）；D2D 对分 REQ 瞬时 50.0%（未打满）；横环 DAT 瞬时 97.9%（打满）；纵环 REQ 瞬时 85.4%（接近打满）。 “打满”看最忙那条 CHI VC 的瞬时峰值是否达到该织物有向边数； 全程平均会把排空尾部算进去，会低估峰值占用。 D2D 对分是 48 对双向 SerDes；bottom 落地后横口、纵口可同时上环。
  5. SWAP + D2D 落地 buffer 解除交叉死锁。S0 SWAP 54,468 次（H↔V 20,134，D2D 34,334）；S1 53,402 次（H↔V 20,130，D2D 33,272）。下降的 WriteData 与上升的 Comp/PCrd 在 D2D bridge 互换 hop；远列转向在横↔纵挂接点互换。落地 buffer 峰值 16。
