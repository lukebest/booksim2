3D 堆叠 NoC：按 top die 分组的写带宽

bottom die 横环 4 cycle / 纵环 6 cycle / 挂接点转向 5 cycle。 workload：burst 128 B、stride 4096 B、 tiling_size 64 KB × 10 tile / core （每核 5120 笔 WriteNoSnp，共 307,200 笔）。 地址按 128 B 交织到 96 个 HA，每核覆盖全部 HA （每核打到同一 HA 的次数 53–54）。 每 core outstanding = 128，每个 HA 最多收 32 个 REQ，超出回 RetryAck。

S0 没有源端流控——只要 outstanding 有空位、ring 上有 slot 就发。 S1 再加 AIMD 源端控速。HA 跟踪表满是完成方反压，不是源端控速。

结论

  1. outstanding 设为 128。 无拥塞的 WriteNoSnp 往返 = REQ 去程 + DBID 回程 + WriteData 去程 （4 flit 流水，最后一拍比第一拍晚 3 cycle）+ Comp 回程。 最坏一对 (core 4, HA 231) 的去程 58 cycle、回程 147 cycle，合计 413 cycle。额度从 REQ 上环一直占到 Comp 回来。 窗口 128 小于最长 RTT 413，长路径上 core 会先把 128 个槽占满再等 Comp。 本批次每 core 5120 笔，大于窗口 128，实测峰值占用 128，outstanding 上限已经打满——S0 能发出去的条件只剩 outstanding 空位和 ring slot。
  2. HA 跟踪表满了就 retry。S0 不另加源端控速，S1 才控速。 每个 HA 同时只能收 32 个请求；再来的 REQ 走 RetryAck → PCrdGrant → 重发 REQ，占真实 RSP/REQ 带宽。 S0 完成 307,200/307,200，makespan 167,061 cycle， RetryAck 99,595 次，有效并发是名义值的 18.9%； S1 完成 307,200/307,200，168,175 cycle， retry 99,082。 两个方案都排空，没有活锁、没有停在停滞检测器上。
  3. 六个 top die 的写带宽均衡。 S0 组间完成量 max/min = 1.00， 组间 Jain 1.0000； S1 为 1.00 / 1.0000。 下图是各 group 写带宽随时间的曲线；die 0 十个核的上环 CW / CCW 成败见第 2.1 节（CC = CW，顺时针）。
