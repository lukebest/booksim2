3D 堆叠 NoC：按 top die 分组的写带宽

bottom die 横环 4 cycle / 纵环 6 cycle / 挂接点转向 5 cycle。 D2D landing 在 bottom die 上有两个独立接口（接横环、接所在列纵环）。 带宽口径为瞬时带宽（滑窗 flit/cycle，并报单周期峰值）。 workload：burst 128 B、stride 4096 B、 tiling_size 64 KB × 4 tile / core （每核 2048 笔 WriteNoSnp，共 122,880 笔）。 地址按 128 B 交织到 96 个 HA，每核覆盖全部 HA （每核打到同一 HA 的次数 21–22）。 每 core outstanding = 512。 每个 HA 跟踪表 32 项，满了走请求 retry （RetryAck → PCrdGrant → 重发 REQ），不是源端控速。

S0 没有源端流控——只要 outstanding 有空位、ring 上有 slot 就发。 S1 再加 AIMD 源端控速。HA 跟踪表满触发的是 CHI 请求 retry，不是源端控速。

结论

  1. outstanding 设为 512。 无拥塞的 WriteNoSnp 往返 = REQ 去程 + DBID 回程 + WriteData 去程 （4 flit 流水，最后一拍比第一拍晚 3 cycle）+ Comp 回程。 最坏一对 (core 4, HA 231) 的去程 58 cycle、回程 147 cycle，合计 413 cycle。额度从 REQ 上环一直占到 Comp 回来。 窗口 512 相对最长 RTT 413，长路径上 core 会先把 512 个槽占满再等 Comp。 本批次每 core 2048 笔，大于窗口 512，实测峰值占用 512，outstanding 上限已经打满——S0 能发出去的条件只剩 outstanding 空位和 ring slot。
  2. HA 跟踪表满是请求 retry 机制。S0 不另加源端控速，S1 才控速。 每个 HA 同时只能收 32 个请求；再来的 REQ 走 RetryAck → PCrdGrant → 重发 REQ，占真实 RSP/REQ 带宽。 S0 完成 122,880/122,880，makespan 93,683 cycle， RetryAck 95,986 次，有效并发是名义值的 12.9%； S1 完成 95,534/122,880，430,685 cycle， retry 97,630。 有方案没有排空，见下表。
  3. 六个 top die 的写带宽不均衡。 S0 组间完成量 max/min = 1.00， 组间 Jain 1.0000； S1 为 1.35 / 0.9898。 下图是各 group 写带宽随时间的曲线；die 0 十个核的上环 CW / CCW 成败见第 2.1 节（CC = CW，顺时针）。
  4. 对分 / 环带宽按瞬时口径看。 S0：top die REQ 瞬时 78.3%（接近打满）；D2D 对分 REQ 瞬时 49.0%（未打满）；横环 REQ 瞬时 95.8%（打满）；纵环 RSP 瞬时 95.8%（打满）。 S1：top die REQ 瞬时 75.0%（接近打满）；D2D 对分 REQ 瞬时 49.0%（未打满）；横环 REQ 瞬时 93.8%（打满）；纵环 RSP 瞬时 99.3%（打满）。 “打满”看最忙那条 CHI VC 的瞬时峰值是否达到该织物有向边数； 全程平均会把排空尾部算进去，会低估峰值占用。 D2D 对分是 48 对双向 SerDes；bottom 落地后横口、纵口可同时上环。
