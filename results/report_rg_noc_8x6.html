1. 建模口径

  • 拓扑：8×6 mesh（82 无向链路）vs 折叠 2D torus（96 无向链路）。金属线恒定约束下 torus 每链路带宽减半（σ=2），对分带宽与 mesh 严格相等。
  • 金属线审计：mesh=82 · torus=96 · 比=1.171（torus 多约 17% 链路单位；折叠线长×2 的物理偏差见敏感度 delay×2）。
  • 控制平面（硬约束）：集中式/分布式 request–grant 消息走私有控制 NoC（与数据面同构的独立物理网络），不与数据面共物理链路。 控制面不继承数据面 σ；单向时延 = ⌊含 link delay 的曼哈顿距离 / 2⌋（XY 路径）； 剩余争用仅来自控制消息互争 + CA 入端口汇聚。
  • 类型：bufferable = 源端 grant 准入 + 路由器 FIFO/credit；bufferless = grant 逐拍预约路径、路由器零缓冲。
  • 仲裁器：CA 集中式 @ (x=4,y=0) = nid 4（原点左上、先 x 后 y，即第 1 行第 5 列）； DA 目的端分布式；CA-batch = CA + 错峰 request + 时间窗批量仲裁 + 全局无冲突排程 BCFS（见 §3）。
  • Request 产生时刻：各节点不同时产生 request（默认每节点 U[0,64) 随机起跳，同一节点内多条 request 逐拍发出）。 到达 CA 的时刻 = 产生时刻 + XY 路由上 ⌊曼哈顿线延迟/2⌋ + 私有控制网争用，因此天然离散。
  • 同步：allgather/allreduce 默认 sync barrier（等齐 48 个 request 再统一 grant）；allgather 另做异步「每 grant = 一棵多播树」对照。 CA-batch 的 W=∞ 即等价于「等齐再仲裁」的同步纪律。
T = T_bound + R_rg + W_grant(ρ)  ;  R_rg = ℓ_ctrl(src→arb) + T_sched + ℓ_ctrl(arb→src)
ℓ_ctrl = ⌊曼哈顿线延迟/2⌋，走私有控制 NoC，与数据面链路资源正交

2. 头条结论：私有控制 NoC 上的收敛税仍是 alltoall 瓶颈

即便 request/grant 完全不占用数据链路，CA 下 alltoall 若对每条 (s,d) 流单独 request，共 48×47=2256 条控制消息仍须挤入仲裁器控制路由器的 ≤4 个入端口。 入端口收敛下界 ⌈2256/4⌉=564 cy；私有控制 NoC DES 实测 t_last_request=1887 cy （超出部分 = 控制消息在私有网上的路径争用，不是数据干扰）。而 m=1 数据面下界仅 ~98 cy、FIFO 基线 makespan=192 cy。

两个有效缓解：

  1. Request 聚合：每源一条 request 覆盖全部目的 → 48 条，t_last_req 降到线延迟量级（~55），makespan 回到与 FIFO 同量级。
  2. DA 分布式：把收敛点打散到 48 个目的节点，消除单点 564 cy 税。

3. 错峰 request → 时间窗批量仲裁 → 全局无冲突排程（CA-batch）

3.1 流水线

中心调度器固定在 (x=4, y=0)（原点左上、先 x 后 y，即第 1 行第 5 列，nid=4）。 控制消息在私有控制 NoC 上走 XY 维序路由； 单向时延取含 link delay 的曼哈顿距离的一半 ℓ_ctrl = ⌊(hx·H + hy·V) / 2⌋（数据面仍用满 H=7 / V=9）。

① 节点 i 在 t_gen(i) 产生 request（各节点不同时）
② request 经 XY 路由到 CA(4,0)：t_arr(i) = t_gen(i) + ℓ_ctrl(i→CA) + 控制网争用
③ CA 关闭长度 W 的滚动时间窗，取窗内到达的一批 request，于 t_decide = max(窗尾, 批内最晚到达) + T_sched 起仲裁
④ grant 经 XY 路由回源：release(i) = t_decide + ℓ_ctrl(CA→i) + 争用
⑤ 数据面起始时刻 t0(i) ≥ release(i)，由 BCFS 决定

CA(4,0)→最远角：数据曼哈顿 mesh 73 / torus 55；控制面各取其半 → mesh 36 cy / torus 27 cy。

3.2 BCFS：点对点请求的全局无冲突排程算法

单条被授权的点对点流是一个刚性时空印记（wormhole、无缓冲）：给定起始 t0、XY 路径 P、m 个 flit， 它在有向链路 e 上的占用区间为

occ(e) = [ t0 + prefP(e) ,   t0 + prefP(e) + m·σ )

其中 prefP(e) 是源到 e 尾端的累计线延迟，σ 为每 flit 拍数（mesh 1 / torus 2）。 「全局无冲突」= 为一批 request 选一组 t0，使任意链路上任意两个印记不重叠，且源/目的 ramp 容量（RAMP_BW=2 flit/cy）不被超出。 这是固定路由的 job-shop 型区间装箱问题（一般情形 NP-hard），BCFS 用三件事求解：

  1. 关键度优先的表调度：先排「路径穿过最拥挤链路」的 request。 定义 pressure(r) = Σe∈P(r) load(e)，load(e) 为本批中使用 e 的流数；pressure 大者裕度最小，先排。
  2. 精确「最早可行起点」搜索：不逐拍试探。对每条链路与两端 ramp 维护区间图， 直接跳到「所有链路 + 两端 ramp 同时空闲」的最早时刻——等价于在已有排程的空洞里做 backfill， 所以后到的短流能填进前面留下的缝隙。
  3. 多起点搜索：以 criticality / longest-path / FCFS / 随机 共 5 种优先序各跑一遍，取批 makespan 最小者。

输出按构造即无冲突，并由独立检查器 verify_conflict_free() 重新逐链路两两复核 （本次全部 79 组配置 conflict_free=✓，bufferless DES 实测 max_residency=0）。 这正是零缓冲数据面能成立的前提：路由器不需要任何 buffer，因为 grant 已经保证了逐拍不撞。

跨窗口的预约持久保留：第 k+1 批在排程时会看到第 k 批已占用的区间，因此全局（而非仅批内）无冲突。

W 的取舍：W→0 退化成逐条即时仲裁（R_rg 最短，但 BCFS 只能看到一两条流，增益≈0）； W→∞ 退化成同步 barrier（视野最全、增益最高，但要付「等最晚 request」的税）。 中间存在最优点：mesh alltoall 聚合 m=4 在 W≈16–64 取到最小 makespan。

6. Mesh vs Torus

  • 对分带宽绑定的大消息 alltoall：二者数据下界相同（bisect 自检 ✓）。
  • 小消息 / 树形（broadcast、reduce）：torus 直径 55 vs mesh 94，DA bufferless broadcast m=1 为 58 vs mesh 97。

9.1 CA-batch / BCFS 专项验证

  • 中心调度器坐标一致为 (4,0)：✓（nid=4）
  • 控制平面 XY 维序路由：✓
  • Request 到达时刻确实离散（spread>0，多源配置 67 组）： ✓ （另有 12 组 broadcast 单源聚合只有 1 条 request，无离散度可言）
  • 全局无冲突（独立检查器逐链路两两复核）：✓ · 冲突数 = 0
  • bufferless 回放零驻留（49 组）：✓ ——零缓冲路由器成立的直接证据
  • 点对点（alltoall/reduce）BCFS 从不劣于 FCFS（43 组）： ✓ · 平均增益 6.1%
  • 全体平均增益 4.1% · 最大 18.1%； 多树 pattern 有 0 组反向（最差 +0.0%）—— 在线窗口局部最优的固有代价，见 §10。

The strict check covers only pairs whose bufferable side ran the cycle-accurate DES. Rows marked approx='event_driven_fast' (48-tree allgather, and 2256-flow alltoall) expand trees into per-destination unicast and admit flits greedily per link, which over-counts shared prefixes and head-of-line stalls; on torus (sigma=2) that inflation is largest. Those rows are conservative upper bounds, not monotonicity failures.

10. 已知局限

  • 数据面金属线：按链路计数 torus/mesh≈1.17，非严格恒定；折叠线长×2 用 torus_delay_scale=2 对照。
  • 私有控制 NoC 是额外金属/面积（每节点 +0.12），不计入 mesh/torus 数据面对分带宽恒定约束。
  • 同 hop 延迟 7/9 对 torus 有利（白拿减半跳数）。
  • 多树 bufferable（allgather）与 2256 流 alltoall 用事件驱动单播展开近似，共享树边被重复计数（保守上界）。
  • BCFS 是在线窗口局部最优：CA 只能给眼前这一批打分，无法预知后续窗口。 多树 pattern（mesh allgather m=16）上出现 0 组「本批更紧、全局更慢」的反向案例（最差 +0.0%）。 点对点 pattern 上未出现。若允许离线全局排程（所有 request 先到齐，即 W=∞）可消除此效应。
  • BCFS 的路径是 XY 维序固定的；允许自适应路由会扩大可行域，但需重做 CDG 无环性论证。
  • reduce = gather + PE 本地归约（无网内算术），对齐 ADR-002/Arch-A2。
