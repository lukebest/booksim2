2. PG 方案详解

实现见 utils/pg_routing.py。所有进入 DES 的表必须同时满足： CDG 无环（无死锁）、每 (src,dst) 唯一路径（保序）、compute 集合连通。 失败时由统一牺牲恢复器禁用额外 good 节点（边界 → 整行/整列 → 矩形屏蔽）。

保序不排斥 VC。保序真正要求的只是「每个 (src,dst) 一条固定路径、 且沿路 VC 序列确定」——只要 VC 是 (src,dst) 的函数而非 per-packet 动态选择， 同一对的包就不会跨 VC 乱序。因此本研究的方案按断环手段分成两大类：

三问的共同底座（各方案只写自己的差异部分）

1. 避障的共同前提：expand_pg 给出的 route_adj 已经删掉了故障节点与断链，任何选路函数只在这张存活图上搜索， 不可能踏进坏点坏边。真正的差异在于「图上搜不到合法路时怎么办」： 绕行（M3/M4/M6/M7/M10）、裁剪（M2/M5），还是直接失败（M1）。 所有方案失败后都落到同一个恢复器 solve_scheme： 先去孤立点，再按「单点 → 点对 → 整行整列 → 矩形」逐级牺牲 good 节点， 取牺牲最少的可行解。

2. 无死锁的共同判据：不管构造上怎么论证，进入 DES 之前一律过 validate_routing → build_cdg(paths, vc_of) + cdg_acyclic。CDG 结点是 (有向边, VC) 二元组， 只要存在环就判不可行。构造性证明只决定「一次过还是要重试」。

3. 保序的共同机制：本研究全部是确定性离线路由—— 每个 (src,dst) 只有一条路径，且 vc_of(path, i) 是 (该对, 跳序号) 的纯函数，运行时不做自适应选路、不做 per-packet VC 竞争选择。 同一对的 flit 序列走同一串 (边, VC)，wormhole 下天然 FIFO ⇒ 保序。 带 LB 的变体只是在离线迭代里换路，最终仍是一对一条固定路径。

A 类 · 转向限制（1 VC）

mesh 的死锁来自「东→北→西→南→东」这样的通道环。A 类的做法是 删掉环上的某一类转弯，让环无法闭合。

代价：被删的转弯同时也删掉了一批最短路，绕路变长、负载更不均。 洞越大，被迫绕得越远。

成员：M0 East-first、M1 XY、M2 Rect-XY、M3 Up*/Down*、M4 Segment。 同一族里禁得越少、可用最短路越多：M0 只禁 2 类转弯，XY 禁 4 类。

B 类 · VC 分层（多 VC）

不动路径，而是给通道编层号，规定报文沿路层号只增不减。 环要闭合就必须从高层回到低层，而这被禁止 → 无环。

代价：每层要独立缓冲与 credit，面积随层数放大； 换来的是路径可以贴近最短路。

成员：M5 真 f-ring（4 VC）、M6 LASH / M6b LASH-TOR（1–2 VC）、 M7 条带 dateline（约 5–6 VC）、M9 双向 Up*/Down*（2 VC）、 M10 虚拟规则网格（2 VC）。

2.1 A 类：转向限制

M0 — East-first turn model（east_first）

类别：A 类 · 转向限制 · 1 VC。Glass–Ni 最小转向模型家族， west-first 的镜像。

思想：XY 禁掉了 4 类转弯（N→E、N→W、S→E、S→W），其实只禁 2 类就够断环。 east-first 只禁「转向东」的两类——N→E 与 S→E（外加一律禁 180° 掉头）， 剩下 6 类转弯全部合法。合法路径集是 XY 的真超集，所以 XY 能走的它都能走， XY 被堵死时它还有绕行余地。

路径形状：没有任何转弯能回到东向，于是每条合法路径必然是 「先在源行里一路直冲东，再只用 N/S/W 走完」。实现上优先取 XY 折线 （XY 本身合法），XY 被堵才退到带来向状态的转向 BFS。

注意：普通 shortest_path(..., allowed_next) 按节点去重， 首次到达的方向会把后续合法转弯悄悄锁死，会误报不可达。M0 用 _turn_bfs 按 (节点, 来向) 去重，所以「不可达」是真不可达。 （M4 Segment 仍用按节点去重的版本，它 17/36 的建表失败里可能含这种搜索不完备的成分。）

如何避障只能向北/南/西绕，不能向东绕。转弯集比 XY 宽，所以纵向链路断、非首列的洞大多能绕过去（36 格里 24 格零牺牲，M1 XY 只有 9 格）。但东向永不可绕：源行东侧一断，该行以东全体失联，这是它 12/36 建不出表的唯一原因（见下表与右下图）。
如何无死锁构造性，且对残图同样成立。2D mesh 的通道依赖环只有两条抽象环：顺时针 W→N→E→S→W 用到 N→E，逆时针 W→S→E→N→W 用到 S→E；east-first 把这两条各断一处，加上禁 180°，CDG 必无环。关键是删链路只会减少转弯、不会创造转弯，所以证明不依赖网格完整——任何故障残图上都无环，1 VC。实测 36 格 CDG 硬校验 0 例成环。
如何保序每对 (s,d) 离线定死一条路径（先试 XY，再试 BFS，两者都是确定性的），单 VC 无自适应 ⇒ 同一对的 flit 顺序经过同一串通道。

M1 — XY（xy）

思想：坚持维序路由（DOR）：先走完 X，再走 Y；硬件几乎不用改路由逻辑。

路径：对每个 (s,d) 严格按 XY 折线前进；所需 hop 被故障删除则整表失败，进入牺牲恢复。

特征：中心/角链路一断极易「穿不过」；恢复时常退化成与 M2 类似的大矩形牺牲。 用于量化「坚持 XY 硬件」要付多少牺牲代价。

如何避障不避——这是它的定义。xy_path 在存活图上死走 XY 折线，任一 hop 缺失立刻返回 None，整表作废。唯一出路是牺牲好节点把「折线必经的洞」移出参与集合，所以牺牲最重。
如何无死锁X 相走完才进 Y 相，Y→X 转弯根本不存在；完整矩形上 XY 的 CDG 是经典无环结论。残图上路径仍是 XY 子集，照样无环，实现仍跑一次 CDG 硬校验。1 VC 即可。
如何保序每对唯一的 XY 折线，单 VC，无自适应 → 同一对的 flit 串行经过同一串通道。

M2 — Rect-XY（rect_xy）

思想：不在破损拓扑上绕路，而是裁成仍规则的子矩形，矩形内继续跑 XY。

做法：(1) 标出故障触及的行/列；(2) 在剩余行、列中各取最长连续段，叉成最大轴对齐矩形； (3) 矩形外原计算节点全部记为 forced_sacrificed；(4) 矩形内生成 XY 全表。

特征：牺牲粗、可预测；raw slowdown 常为负是因为参与者变少——应看 irregularity_penalty 与 sacrifice_cost。

如何避障靠裁剪，不靠绕行。把故障触及的整行整列全部划掉（_fault_rows_cols），在剩余行列里各取最长连续段，叉出最大轴对齐矩形；矩形外的好节点记为 forced_sacrificed。于是路由域内一个洞都没有，不需要任何避障逻辑。
如何无死锁子矩形是一张完整规则 mesh，其上跑标准 XY ⇒ CDG 无环（与 M1 同理），1 VC。
如何保序矩形内每对唯一 XY 路径，单 VC，确定性。

M3 — Up*/Down*（updown）

类别：A 类 · 转向限制 · 1 VC（无需虚拟通道分层）。

思想：在任意连通的存活路由图上，先建一棵以某个根为中心的生成树标号， 再强制报文只走「先朝根（up）、再离根（down）」的路径。 这是不规则拓扑上最经典的无死锁确定性路由（Glass–Ni / Autonet Up*/Down*）。 故障后只要图仍连通，通常就能零牺牲跑通全表——本研究里它是「保住计算规模」的基线。

算法步骤：

  1. 选根：在存活路由邻接表上取度最大的节点（并列取编号小者），尽量让树更「中心」。 每种故障场景只选一次，所有 (s,d) 共用（见图③）。
  2. 标号：从根做 BFS，label(n) = dist(root, n)。 朝根走（label 减小）= up；离根走（label 增大）或同层侧向 = down。
  3. 转向规则：路径分两相——相 0 允许 up；一旦走出 down，进入相 1， 此后禁止再 up。同层侧向也算 down，因此不能「下完又上」。
  4. 选路：在上述合法转移上对 route_adj 做 BFS， 得到每对 (s,d) 的最短合法路径——不是 XY/DOR，也不是「先走到根再离开」。 整表确定性、唯一路径 → 同源同目的保序。

Q1. root 是每种故障一个，还是每个 (src,dst) 一个？
每种故障场景（一份存活路由图）只选一个 root。 换 (s,d) 不换 root；换故障 / 牺牲后图变了，root 才可能变（度最大点可能换人）。 见图③：S₁→D₁ 与 S₂→D₂ 共用同一套 d=… 标号。

Q2. src→root、root→dst 还是 DOR 吗？
都不是。实现是「约束 BFS」：在活边上枚举邻居，只按 label 升降判断 up/down 是否合法，取最短跳数路径。跳的方向可以是任意 mesh 邻边（东/西/南/北）， 与「先 X 后 Y」无关。见图④红虚线（DOR 撞洞）vs 彩实线（Up*/Down* 绕开）。

Q3. 路径必须经过 root 吗？
不必。Root 只提供高度坐标系，不是中转站。 路径可以过根（图①，S、D 分居两侧时常见），也可以完全不过根 （图②：d=2→1→2，只在顶行走）。示意图画「S→根→D」是为展示两相， 不是算法字面步骤。

Q4. 怎么避开故障节点？
建图时就删掉了。expand_pg 生成的 route_adj 不含 dead 节点及其入射边（transit 语义下故障节点不当 compute，但 router 可仍在图中）。 _tree_path 只遍历 adj.get(u)，不可能踏进已删除的点/边。 若图被割裂或「先上后下」下无合法路，则该场景失败，外层再靠牺牲好节点恢复。

如何避障约束 BFS 自动绕。_tree_path 只枚举 route_adj 的邻居，洞和断链根本不在候选里；它在存活图上找「先上后下」的最短合法路，形状可以是任意折线（不是 XY、不必过 root）。只要图连通且合法相位下有解，通常零牺牲——这是 M3 最大的优点。无解才交给统一牺牲恢复器。
如何无死锁给每点一个高度 label = BFS dist(root, ·)；规定路径分两相：相 0 可 up，一旦 down 就永远禁止再 up（同层侧向算 down）。通道依赖只能是 up→up、up→down、down→down，永远没有 down→up，所以依赖关系随 (相位, 高度) 单调 ⇒ CDG 按构造无环，1 VC 够用。实现仍硬校验。
如何保序root 与 label 每个故障场景只算一次、全表共享；给定 (s,d) 的约束 BFS 结果确定且唯一，单 VC。

目录外会不会连通却不可达？ 不会。单/双故障全枚举 + 三节点全量 17296 + 随机混合 5000： 失败集合与残图断连完全重合，STRUCT=0。 连通残图上 UD 必有合法路；不可达时只牺牲孤立点/小子图。见 §2.3。

与本网格实测：dead/transit 下几乎全部场景 n_sacrificed = 0（A≈39–48）， 是 1 VC 方案里规模保持最好的；但合法路径集合窄，负载集中在树的「脊」， alltoall makespan / irreg 明显高于最短路族（M6/M7/M10）。 M3+LB 试图在合法集合内做负载感知换路，本 8×6 上中位收益几乎为零。 换根搜索（M3′）与分批屏障（Batch-Barrier）见下两节。

端到端角色：库存「度最大根」基线。同面积上通常被 M3′ 支配； 分批屏障计入同步后是否仍优，见 §6。

M3′ — Up*/Down* best-root（updown_best_root）

类别：A 类 · 与 M3 同构的转向限制 · 1 VC。

思想：Up*/Down* 的唯一自由参数是生成树根（高度坐标系原点）。 库存 M3 取「度最大」启发式；M3′ 在全部存活 router上穷举根， 对每张候选全表算 alltoall 最大链路负载，取 (max_link_load, total_hops, root_id) 字典序最小者。 死锁自由与避障论证与 M3 完全相同——只是换了一套标号。

算法步骤：

  1. 对每个候选 root ∈ 存活邻接表，跑与 M3 相同的约束 BFS 建全表；CDG 校验失败则丢弃。
  2. 在合法表上统计有向边 alltoall 对数负载，记录 max_link_load 与总跳数。
  3. 选最优 root；运行时仍是单张静态路径表（每对唯一路径）。

与本网格实测（预算故障 44 场景）：相对库存 M3， 最差端到端 m₀=1：893→790 ns（−11.6%）；m₀=13：7678→7573 ns（−1.4%）。 中位收益更大（负载更均衡），但最差场景仍受「单高度函数」瓶颈限制。

端到端角色：「仍坚持单表、单波 alltoall」时的最佳 1VC 点。 分批屏障（计入批间同步）是否更快见 §6。

如何避障与 M3 相同：只在 route_adj 上约束 BFS；根搜索不改变存活图。
如何无死锁每张候选表仍禁止 down→up，按构造 1VC 无死锁；实现仍硬校验。
如何保序选定根后全表唯一路径，与 M3 相同。

M3+LB — Up*/Down* + 负载均衡（updown_lb）

在 M3 路径表上后处理：统计有向边 alltoall 对数负载；每轮重排途经最热边的若干 (s,d)， 用负载感知 Dijkstra（边权 ≈ 1+负载）换路；每轮后整表再校验 CDG。失败则回退。

特征：目标是压低最大链路负载；在本 8×6 上对 median makespan 改善通常很小 （Up*/Down* 合法路径集合较窄）。相对「换根」几乎无额外收益——合法集合已被根钉死。

如何避障与 M3 完全相同——换路仍在同一张存活图、同一套合法转向集合内进行，不会新引入穿越故障的路径。
如何无死锁靠「换完再验」而不是靠构造。负载感知 Dijkstra 可能选出破坏原有相位单调性的路径，所以每一轮结束都对整表重跑 validate_routing；一旦 CDG 出环，立刻整体回退到上一个已验证的 best 并停止迭代。
如何保序LB 是离线迭代：收敛后每对仍只有一条固定路径，运行时不会按实时负载改路 ⇒ 保序不受影响。

Batch-Barrier — 分批屏障（bb_*）

类别：调度层 · 运行时物理 1 VC · 不是链路 TDM，也不是「把一张会死锁的整表硬切开」。 统一时序： T_comm = Σi makespan(batchi) + (K−1)·T_sync， 其中 T_sync = 2·radiuswire：残图上选最小化 线延迟离心率的中心，gather→broadcast； 距离用与 DES 相同的 link_lat（横向 H=7、纵向 V=9），Dijkstra 最短路。 旧 hop 模型 2·radiushops≈14 cy 低估同步税约一个数量级。 每批 DES 已含排空。把多 VC 母方案串成 1VC 必然更慢（层无法再并发）——对照的意义是 省面积后相对其他 1VC 方案是否仍优，不是和母方案比速度。

何谓「按 OD 整层切开」： 母方案若满足——每个 OD 对 (s,d) 整条路径锁在同一层 （同一 VC / 同一路由表），从不中途换层——则层号构成 OD 集合的一个划分： batch_k = {全部 which[(s,d)]=k 的 OD}。 每批是完整 OD 子集，批内路径自洽、可单独在 1VC 上验证 CDG。 这就是「按 OD 整层切开 → 一层一批」。Dual-UD、LASH（整路径锁层）、多根 UD 表分配都满足。 不满足的例子：Stripe / Virtual / LASH-TOR——VC 随跳数在路径上递增或切换， 层标签标在边/跳上而非 OD 上；一个 OD 会同时出现在多层，无法拆成「整 OD 进一批」。 本轮因此不做它们的 BB 变体。

BB UD×2（bb_ud_bal2）

BB DualUD→1VC（bb_dual）

母方案：M9 Dual Up*/Down*——物理 2 VC，VC0 跑 UD、VC1 跑 DU； 每 (s,d) 选更短一层并整路径锁在该 VC（满足按 OD 整层切开）。

分批：batch_k = {which[(s,d)]=k}，k∈{0,1}； 每批单物理 VC 只跑该层路径表，批间图中心 barrier。面积按 1VC。 与并发 Dual 比必然更慢（预期）；与同面积的 BB UD 比，多根分批通常更均衡 （最差约 960 / 7535 ns）。

BB LASH→1VC（bb_lash）

母方案：M6 LASH——最短路贪心装入最少无环 CDG 层， 每对整路径锁一层（可按 OD 切开；层数=物理 VC，本目录常 2–3）。

分批：一层一批，1VC 串行 + barrier。相对并发 LASH 更慢是预期； 相对 BB UD，层负载更不均、长尾层拖垮总和（最差约 1048 / 8663 ns）。

端到端角色：线延迟同步税下，重载荷推 BB UD policy；轻载荷分批不划算。 BB Dual / BB LASH 仅作「OD 可切多层 → 1VC」对照。

如何避障BB UD：每批是一张存活图上的 UD 表；BB Dual/LASH：每批是母方案某一 VC 层上的完整 OD 子集。
如何无死锁批内 CDG 无环（1VC）；批间屏障保证排空后再注入——不把多批依赖叠进同一 CDG。
如何保序批内每对唯一路径；批间由屏障分隔，不要求单次全局同时注入。

M4 — Segment / 奇偶转向（segment）

思想：简化 segment-based / odd-even 族：按列带施加不同转向禁令，打破 mesh 环依赖。

转向规则（列段宽 2，seg=(x//2)%2）：直行允许、180° 禁止； 偶段禁 北→东 / 南→西；奇段禁 北→西 / 南→东。路径 = 约束下最短路。

特征：介于 XY 与 Up*/Down*——有时零牺牲，中心故障时常需矩形化。

如何避障shortest_path(s, d, adj, turn_ok) 在存活图上做带转向过滤的 BFS：洞不在邻接表里，自然绕过。比 M1 灵活（可上下绕），比 M3 严格（转向禁令可能把某些绕行方向堵死）→ 中心大洞时常搜不到路，需要牺牲。
如何无死锁按列带交替施加转向禁令（seg=(x//2)%2）：偶段禁 北→东 / 南→西，奇段禁 北→西 / 南→东，并全局禁 180° 掉头。这属于奇偶转向模型族，每个方向环都缺一个必需转弯 ⇒ 环无法闭合，1 VC。残图上仍以 CDG 硬校验兜底——但实测残图上会失效（见下）。
如何保序给定 (s,d) 的约束 BFS 确定性求解，路径唯一，单 VC。

目录外会不会连通却不可达？ 会，而且极常见。单链路 72/82、双链路 3272/3321 在残图仍连通时 建不出表（路径失败或 CDG 成环）。奇偶转向在残图上既堵绕行又破无环假设。 补救：统一牺牲恢复（代价重），或换 M3/M6/M7。见 §2.3。

M4+LB — Segment + 负载均衡（segment_lb）

与 M3+LB 相同流程，起点换成 M4 路径表；同样受转向合法集合限制。

如何避障同 M4：换路仍在同一存活图上，不会产生穿越故障的路径。
如何无死锁同 M3+LB：每轮换路后整表重跑 CDG 校验，出环即回退到上一 best。
如何保序离线迭代，收敛后一对一条固定路径，单 VC。

M5 — 真 Fault-ring + 4 VC（fault_ring_vc）

类别：B 类 · VC 分层 · 固定 4 VC。保留 XY（e-cube）硬件语义的容错路由。

思想：Boppana–Chalasani 式真 fault-ring。把故障吸收进若干互不重叠的 矩形故障块；块外围一圈健康节点构成 fault ring。底层路由仍是「先 X 后 Y」： 不撞块就走普通 XY；下一步会踏进块时，改沿 ring 绕到块的对面，再回到原行/原列继续 XY。

块怎么造：

  1. 种子 = 故障节点 ∪（链路故障贪心选出的端点，见下）∪ 路由死节点。
  2. 每个种子先成 1×1 矩形；若两矩形接触或重叠则合并包围盒，直到稳定。
  3. 块内全部节点从路由图剔除；compute 集也去掉这些点（forced sacrifice）。

链路故障的固有代价：矩形块模型没有「两活节点之间断一条链」的状态， 必须退休一个端点把它变成 1×1 块（辅图）。实现用贪心集合覆盖：每轮选覆盖最多残留坏链的端点。 因此——纯节点故障通常零额外牺牲；纯链路故障要付 1–4 个好节点。这是相对 M3/M7/M10 的固有税。

路径构造（_fring_path）：

  1. X 相：朝目的列一步步走。下一步坐标落在块内 → 调用 _x_detour： 先竖走到环的上/下边（优先朝目的行一侧），再水平走到块远侧列，必要时竖走回原行。 若目的列本身落在块内，则水平停在目的列（避免冲过块再也收敛不了）。
  2. Y 相：X 相结束后（可能已被绕行带到别的行），按当前行→目的行方向走； 撞块则 _y_detour 左右绕，回到原列后再继续。

四条 VC（相位 × 方向，整路径确定性 → 保序）：

VC0X 相 · 东行VC1X 相 · 西行
VC2Y 相 · 北行VC3Y 相 · 南行

X 相 hop 数 = 到达目的列之前的物理跳数；之后全部进 Y 相 VC。 方向类按「源→目的的 X 符号 / Y 相实际行进符号」在离线时固化进 vc_of。

无死锁（可证）：

  • X 相绕行只允许「竖走」或「朝本报文的 X 方向走」→ VC0 内每条横向通道都朝东。 环要闭合必须让 x 回到起点，于是环内不能含横向通道；纯竖环又需要 180° 掉头， 而构造不产生掉头 → VC0 无环（VC1 对称）。
  • Y 相镜像：VC2 内每条竖向通道朝北（VC3 朝南）。
  • 报文只从 X 相进 Y 相、从不回头 → 依赖 {VC0,VC1}→{VC2,VC3} 单向。 单 VC 无环 + 组间单向 ⇒ 整张 CDG 无环。

固有绕路：绕行后常要回到原行再续 XY（图中竖上环、横穿、再竖下）， 这是换取「X 相严格单调 ⇒ 4 VC 可证」所付的代价；负载通常高于 M7/M10。

端到端角色：被 M10 严格支配——M10 面积更小（1.244 vs 1.937） 且两个载荷下都更快（525/5302 ns vs 555/5469 ns）。 （M10 去掉绕路回环之前，M5 曾在 m₀=13 的严格前沿上。） 若硬件已按 XY+绕障做死、且愿意付 4 VC，它仍是「保 XY 语义」的正统答案。

如何避障矩形块 + 沿环绕行。先把所有故障吸收进互不重叠的矩形块（接触即合并包围盒），块内节点整体退出路由图与 compute 集；块外贴边一圈健康节点即 fault ring。路由仍是 XY，只有「下一步会踏进块」时才改走 ring：绕到块的远侧，再回原行/原列续 XY。代价：矩形模型表达不了「两活节点之间断一条链」，必须贪心退休一个端点变成 1×1 块 ⇒ 纯链路故障要付 1–4 个好节点。
如何无死锁4 VC = 相位 × 方向（VC0/1 = X 相东/西，VC2/3 = Y 相北/南），是可证的：X 相绕行只允许竖走或朝本报文的 X 方向走 ⇒ VC0 内所有横向通道一律朝东，环要闭合就得让 x 回到起点，故环内不能有横向通道；纯竖环又需 180° 掉头，构造不产生 ⇒ VC0 无环（VC1/2/3 对称）。报文只从 X 相进 Y 相、从不回头 ⇒ {VC0,VC1} → {VC2,VC3} 单向。单层无环 + 层间单向 ⇒ 整图无环。
如何保序路径与 VC 都在离线固化：meta[(s,d)] 记下 X 相跳数与两个方向类，vc_of 只按 hop 序号查表 ⇒ 同一对的 VC 序列完全确定。

目录外会不会连通却不可达？ 会。两类：(1) 链路故障 → 强制退休端点（多数仍可出表）； (2) 故障块贴在左右边中段（如死节点 (0|7, y)，y∈{1..4}）时 环绕缺侧向空间 → STRUCT（单链 12/82、单点 8/48）。 补救：端点退休；再不行 solve_scheme 多牺牲 1–2 点。见 §2.3。

M6 — LASH（lash）

思想：Skeie 等 Layered Shortest Path。每对取一条最短路（可绕障）， 再把全部路径贪心装进尽可能少的 VC 层，使每层 CDG 无环。 路径质量与无死锁解耦——断环靠分层，不靠砍转弯。

做法：(1) 存活路由图上 BFS 最短路；(2) 按路径长度降序，尝试放入已有层， 加入后若该层 CDG 仍无环则收下，否则开新层；(3) 整条路径使用同一层号（常数 VC） → 保序。本 8×6 上实测通常 1–2 层。

与 M5 差别：不强制矩形块、不强制绕回原行；链路故障只需牺牲孤立节点 （度 0），不必把端点做成块。负载往往低于 f-ring。

如何避障纯图搜索。直接在存活图上 BFS 最短路，洞和断链天然被绕开，路径形状不受任何转向或矩形约束 ⇒ 路径质量最好的一档。不造块、不退休链路端点；只有度为 0 的孤立点必须先牺牲（它谁也连不上）。
如何无死锁把无死锁从路径里剥离出来，交给分层。按路径长度降序遍历所有 (s,d)：试着把整条路径加进第 li 层的 CDG，加完仍无环就收下，出环就撤销、试下一层，都不行才开新层（上限 8 层）。每层各自维护 CDG、互不共享通道 ⇒ 层内无环 + 层间无依赖 ⇒ 全局无环。本 8×6 上通常只需 1–2 层。
如何保序整条路径同一层号（常数 VC，vc_of 忽略 hop 序号只查 (s,d)），加上路径唯一 ⇒ 严格保序。

目录外会不会连通却不可达？ 实测不会。双故障全量 + 三节点抽样 4000 + 混合 5000： 失败 = 断连，STRUCT=0；VC 最多 3（≪ 上限 8）。 理论上层数封顶才可能 STRUCT——本次未观察到。 断连时牺牲；若真层满则抬 LASH_MAX_LAYERS / 用 LASH-TOR。见 §2.3。

M6b — LASH-TOR（lash_tor）

思想：在 LASH 上允许路径中途升一层（Trail / Transition On Route）： hop 的 VC 沿路单调不减，从而把本来需要新开一层的路径塞进已有层。

做法：先尝试整路径入单层；失败则枚举分割点，前半段层 lo、后半段层 hi≥lo，分别维护层内 CDG。本 8×6 上 LASH 已是 1–2 层，TOR 收益通常很小。

如何避障与 M6 完全相同：存活图上 BFS 最短路，先牺牲孤立点。TOR 只改层分配，不改路径。
如何无死锁在 M6 的「层内 CDG 无环」之上，额外允许一次中途升层：前段走 lo、后段走 hi ≥ lo，两段分别记入各自层的 CDG 并各自校验。因为 hop 的 VC 单调不减，跨层依赖只能由低指向高、回不去 ⇒ 层间依然单向无环。
如何保序分割点与两个层号都在离线贪心时固定，vc_of(path, i) 查的是预存的 per-hop VC 表 ⇒ 同一对序列确定。

M7 — 条带 dateline（stripe_vc）

类别：B 类 · VC 分层 · 本网格实测 5–6 VC（按场景中最坏跨越数定尺寸）。

思想：把 mesh 竖切成条带，条带边界就是 dateline（类似环形拓扑破环的日期线）。 路径本身尽量走最短路（优先 XY，不通再 BFS）；无死锁不靠砍转弯，而靠跨带时升 VC。 每条路径上 VC 沿途单调不减 → 天然无环，实现极简。

算法步骤：

  1. 选路：对每个 (s,d)，先试 xy_path；若因故障不通，退回 shortest_path。路径固定后不再改 → 保序。
  2. 确定 dateline（见下「Dateline 如何确定」）→ 得到竖向边界集合。
  3. 赋 VC：报文走第 i 跳时， VC(i) = 此前（含本跳）水平跨越 dateline 的次数。 竖走不跨带，VC 不变；每水平穿一条虚线，VC+1。
  4. 定尺寸：num_vc = 1 + max 跨越数（按本场景最坏路径）。

Dateline 如何确定？

Dateline 是画在列与列之间的竖线（实现用列坐标 d：水平 hop 从列 a 到 b 且区间覆盖 d 即算跨越）。集合只由列几何 + 故障列 + CDG 是否过关 决定，与流量、报文长度、makespan 无关。

  1. 基础稀疏带（width=2）： range(width, MX, width) → 8×6 上即 {2, 4, 6}。条带越窄，DL 越密，东西向路径跨越次数越多，VC 越高。
  2. 故障列加密：从 dead 节点所在列、断链两端点列收集 fcols；对每个故障列 x，再并入边界 x 与 x+1（右邻）。绕障多在故障列附近拐弯， 加密后跨带更勤、VC 升得更快，降低稀疏带里绕出通道环的概率（图③）。
  3. CDG 密封顶：用「基础 + 故障加密」建 vc_of 后做 CDG； 无环则采用；仍有环则退化为每个列边界都是 dateline （1..MX-1），再校验。本实现仍做硬校验，失败则方案失败。

间接关系：路径形状（XY / 绕障最短路）× DL 集合 → 跨越次数 → num_vc。东西跨度大、弯得多的 (s,d) 通常贡献最大跨越数。

如何避开故障？

1. 故障先从路由图里删掉。 expand_pg 生成的 route_adj 已不含 dead 节点 / 断链 （transit 语义下故障节点可不参与 compute，但 router 仍可转发）。 M7 不造矩形块、不退休链路端点（对比 M5），活着的点边都还能用。

2. 选路时「能 XY 就 XY，撞障就绕」。 对每个 (s,d)：

  • 先在存活邻接表上跑 xy_path——若 XY 折线上没有故障，路径与健康网格相同；
  • XY 某跳不存在（节点洞或断链）→ 该函数返回 None，改走 shortest_path（BFS），在活边上绕过故障到达目的地。

因此避障完全是图搜索绕行：没有 f-ring 的「撞块→沿环→回原行」， 路径可以是任意形状的最短路。某对在活图上仍不可达 → 整方案失败， 外层 solve_scheme 再靠牺牲孤立点 / good 节点恢复。

3. Dateline 加密是为无死锁，不是为避障。 绕障后路径更弯，可能在稀疏条带里绕出通道环——故故障列附近多插 DL， 并在必要时加密封顶（见上）。换句话说—— 避障靠最短路，破环靠升 VC；两者解耦。

4. 与 M5 / M10 对比。 链路故障时 M5 必须退休端点做成块；M7 只要图仍连通就可零牺牲绕过去。 M10 用「逻辑 XY + 固定展开表」绕障；M7 直接在物理图上求最短路， 通常更短，代价是 VC 数随跨带次数涨到 5–6。

无死锁：沿任意路径 VC 只增不减。通道依赖 (e, vc) → (e′, vc′) 满足 vc′ ≥ vc； 同层内若路径本身无环依赖，跨层又只能「升」——整体 CDG 无环。 本实现仍做硬校验，失败则加密封顶。

与 M5 / M6 / M10 的差别：

  • 相对 M5：不强制矩形块、不强制绕回原行；链路故障通常只牺牲孤立点，不必退休端点。 路径更短、负载更低，但 VC 更多（5–6 vs 4）。
  • 相对 M6 LASH：不需要离线贪心装层；逻辑就是「跨带 +1」，硬件几乎只是计数器。 代价是 VC 上限更高（LASH 常 1–2 层就够）。
  • 相对 M10：路径质量相近或更好（真最短路），但面积贵一截（VC6≈2.63 vs VC2≈1.24）。

端到端角色：本轮不参与选型（需 5–9 条物理 VC）。 描述保留；延迟极限好但面积贵，不符合「少物理 VC」约束。

右图：① 跨 DL 升 VC · ② 竖走不升层 · ③ 故障列加密 DL · ④ VC 单调 ⇒ CDG 无环。

如何避障能 XY 就 XY，撞障就走最短路。先在存活图上试 xy_path——若 XY 折线没碰到故障，路径与健康网格一模一样；某跳不存在则改用 BFS shortest_path 绕过去。不造块、不退休端点，活着的点边全都能用，通常只需牺牲孤立点。Dateline 与避障无关（详见上）。
如何无死锁跨一条 dateline 就 VC+1，因此沿任意路径 VC 单调不减。通道依赖 (e,vc) → (e′,vc′) 恒有 vc′ ≥ vc：环若要闭合必须从高层降回低层，而这被禁止 ⇒ 只剩「同层内成环」一种可能，而条带内水平跨度被 DL 限死。实现仍硬校验，出环就把 DL 加密到每个列边界再验。代价是 5–6 VC。
如何保序路径固定；vc_of(path, i) = 前 i 跳的跨越数，是 (路径, hop 序号) 的纯函数、离线即可算全 ⇒ 同一对的 (边, VC) 序列唯一。

目录外会不会连通却不可达？ 实测不会。与 M6 相同的故障空间：失败 = 断连，STRUCT=0。 最密 dateline（每列边界）兜底未在实测中被打穿。 断连时牺牲；极罕见再加密 dateline。见 §2.3。

M9 — 双向 Up*/Down*（dual_updown）

思想：VC0 跑经典 Up*/Down*（先上后下），VC1 跑对称的 Down*/Up*（先下后上）； 每对选更短的那条，整路径固定在所选 VC → 保序。

特征：固定 2 VC，实现比 LASH 简单；路径短于单层 Up*/Down*，但通常仍长于最短路族。

如何避障与 M3 相同的约束 BFS，但两套规则各搜一次：Up*/Down* 与 Down*/Up*。某一套被故障堵死时另一套往往仍有解，两条都无解才算失败 ⇒ 可行性略好于单层 M3。
如何无死锁两套相位规则各自满足「不许回头」（UD 无 down→up，DU 无 up→down），各自 CDG 无环；两者放在不同 VC 上、整条路径不混用，所以两层之间没有任何通道依赖 ⇒ 并集仍无环。固定 2 VC。
如何保序每对选哪套规则由 which[(s,d)] 离线定死（取更短者），整条路径锁在该 VC 上、中途不切换 ⇒ 路径与 VC 都唯一。

M10 — 虚拟规则网格（virtual_mesh）

类别：B 类 · VC 分层 · 固定 2 VC。上层软件仍看见完整规则 8×6 XY mesh。

思想：把「逻辑拓扑」和「物理走线」拆开。逻辑层永远是健康的 8×6 全网格 + 经典 XY； 物理上某条逻辑边坏了（节点洞或链路断），就用一条预先算好的、固定的物理最短绕路替换它。 对编译器 / 映射层来说，集合通信调度、坐标寻址都不用改——缺的只是 NoC 内部把逻辑 hop 展开。

算法步骤：

  1. 存活集：至少有一条活链路的节点才算逻辑路由器；孤立点 forced-sacrifice。
  2. 预计算展开表：对每一对逻辑相邻的活节点 (a,b)，若物理直连存在则 expand[a→b]=[a,b]；否则 shortest_path(a,b) 作为该逻辑边的固定绕路。 绕路离线算一次、全局共享 → 确定性。
  3. 逻辑 XY：忽略故障，在完整网格上走先 X 后 Y，得到逻辑折线 full = _logical_xy(s,d)。
  4. 物理展开：丢掉折线上的死节点得 way（须仍以 s 开头、d 结尾）； 依次把 way[i]→way[i+1] 用展开表（或临时最短路）拼成物理路径。
  5. 去回环（_trim_revisits）：拼出来的路径可能重复访问同一节点 （见下「掉头」FAQ），把两次访问之间那段环删掉。 先用去环版建表；若 CDG 成环则整表退回未去环版，两版都成环才返回 None。
  6. VC 划分：物理 hop 在「首次到达目的列」之前 → VC0（逻辑 X 相）； 之后 → VC1（逻辑 Y 相）。即使 X 相里含有竖向绕路 hop，仍算 VC0—— 分层按逻辑相位，不按物理边方向。
如何避障逻辑层假装网格完好，物理层偷偷绕。坏掉的逻辑边被一条离线算好、全局共享的固定物理最短路替换（expand[a→b]）；逻辑折线上的死节点直接跳过，再把相邻的活节点桥接起来。孤立点 forced-sacrifice。对上层软件而言故障是不可见的——仍是规则 8×6 XY，映射与调度不用改。
如何无死锁意图是维度序：VC0 = 逻辑 X 相，VC1 = 逻辑 Y 相，相位只能 X→Y 单向切换。但 VC 只按相位切、不按方向切，同一层里既有东行也有西行；绕路又会往 VC0 塞竖边、往 VC1 塞横边 ⇒ 几何证明失效，确实会成环（见下 FAQ 的实测反例）。所以 gen_virtual_mesh 内部直接调 validate_routing 硬校验，并按「去环版 → 未去环版」两次尝试；都不过才返回 None 转入牺牲恢复。固定 2 VC。
如何保序expand 表离线固定且全局共享，逻辑折线由 (s,d) 唯一决定 ⇒ 物理路径唯一；去环是确定性后处理，选哪一版是整表级决定 ⇒ 同一对的路径与 VC 序列仍唯一。

最小失效实例 (1,0) (3,1) (5,1)，两版成环机理完全不同（上图）：

  • 原始拼接版 = 2 通道掉头环。绕路走过头，后续逻辑跳原路折回， (2,1)→(2,0) 与 (2,0)→(2,1) 同处 VC1 互相等待。 这正是引入去回环的原因。
  • 去回环版 = 8 通道矩形环，全在 VC0。去环消掉了掉头， 但缩短后的路径贴着洞走，绕死节点 (3,1) 首尾相接闭合成经典通道环。

根因在 VC 划分：M10 按逻辑相位分 VC，而死节点逼出的绕路会在逻辑 X 相里 走物理竖直跳，这些竖直通道落进 VC0。于是 VC0 里同时存在横向与纵向通道、 又没有任何转向限制 —— XY 的无环论证在此失效。这与 M7 靠 dateline 单调升 VC、 M6 靠分层校验、M5 靠「相位×方向」四层的可证断环有本质区别。

成环了怎么办：两版都成环 → gen_virtual_mesh 返回 None → solve_scheme 按「孤立点 → 单点 → 点对 → k≤6 → 整行整列 → 矩形」 逐级牺牲 good 节点并重新生成、重新校验，取牺牲最少的可行解；全失败才判 INFEASIBLE。 上面的最小实例实测牺牲 1 个节点 (0,0)（A=44/45）， 同故障下 M7 / M6 / M3 牺牲 0 —— 代价不大，但这就是「有证明」与「靠试」的差距。 目录外 STRUCT / disc 对照表见 §2.3。

与 M5 / M7 的关键差别：

  • 相对 M5：不造矩形块、不强制绕回原行；链路故障不必退休端点，牺牲更少。 VC 只要 2 条（vs 4）。去掉绕路回环后端到端严格快于 M5 且面积更小， 把 f-ring 挤出了 Pareto 前沿。
  • 相对 M7：路径不是全局最短路，而是「逻辑 XY + 局部展开」，有时多走几跳； 但 VC 固定为 2，面积约 1.24（vs Stripe 的 2.63），是性价比拐点。
  • 相对 M3：多 1 条 VC，换来接近最短路的路径质量和显著更低的 makespan / 端到端时间；上层映射还保持规则网格。

6. 端到端时间 × 面积 Pareto

按纯 makespan 排序会误导——M1 XY 的 makespan 最小， 但中位牺牲 28/48 个节点（这正是它被 §2.5 排除出第 3–4 节对比的原因）。 把通信放回真实计算任务后，牺牲的代价才显现，就可以在同一把尺子上重新比较。 本节用 端到端任务完成时间（计算 + alltoall）与 router 面积 构造 Pareto 前沿，把被排除的方案也一并放回，量化它们到底差多少。

6.1 模型

  • 任务：MoE 专家并行 FFN 的 dispatch 半程 — alltoall → 专家 FFN，串行不重叠 （完整层还有对称的 combine alltoall，会让通信项翻倍；此处略去以对齐「一次 alltoall」口径）。
  • 计算：PE 每拍一次 8×64×16 matmul = 8192 MAC/cy @ 1.5 GHz。FFN d_model=64、 d_ff=256、fp16 —— 8×64×16 恰好整除两层 matmul， 无 tile 量化浪费，4 拍/token。 token = 128 B = 2 flits （flit = 64 B）。
  • 强扩展：总 token 钉在健康 48-PE 配置（每对载荷 = 标称 m₀）： T_total = 48²·m₀·64B/128B = 1152·m₀ tokens。 只剩 A 个存活 PE 时两项同时变重： T_compute = ceil(4·T_total/A)； m_eff = ceil(m₀·(48/A)²)（通信也必须重标定，否则重牺牲方案白拿 1/A² 流量减免）； T_e2e = T_compute + T_alltoall(m_eff) → ns @ 1.5 GHz。
  • 面积（仅 router）：牺牲的 PE 只计时间不计面积；48 个 router 始终物理存在， 唯一杠杆是 VC 数。归一化到 IQ-XY 基线 = 1.0： area = crossbar(0.38) + control(0.17) + 5 port × VC × Q(19) × 0.00365。 DES 中 Q 是每 VC 深度，故 VC 数线性放大缓冲。 每个方案按全部场景中需要的最大 VC 数定尺寸。

故障模型：≤4 router + ≤8 无向链路（双向算 1，与 router 不重叠）， 分层随机抽样 44 场景 （不再使用旧 link_/node_ corner/edge/center 目录）。 评估范围：M3 族 / Super-turn / Dual-UD / LASH（≤3 VC）与 分批屏障 1VC（bb_*）。 不含需多物理 VC 的 Virtual mesh / Stripe / f-ring（§2 描述保留）。 批间同步：图中心 gather+broadcast， T_sync=2·radius_wire（Dijkstra + link_lat，H=7/V=9，与 DES 一致）。 数据 results/pg_e2e_pareto.json / results/pg_batch_barrier_e2e.json。 共 1536 行（含描述外方案原始行时以表为准）。

6.3 选型结论

  1. 排名翻转仍成立：M1/M2/M4 裸 makespan 好看，端到端被低牺牲方案支配。
  2. 通信占端到端 70–86%（除重牺牲方案）。花 router 面积买带宽划算。
  3. 分批屏障 vs 有限 VC： 批间同步为图中心 gather+broadcast， T_sync=2·radius_wire（按 link_lat H=7/V=9，与 DES 同口径； 健康 8×6 上约百拍量级，远高于旧 hop 模型的 ≈14 cy）。 bb_ud_* 相对单表 M3′ 的优势以同步税计入后的 §6 数字为准。 把 Dual/LASH 按 OD 整层切开串成 1VC（bb_dual/bb_lash） 相对母方案更慢是预期；同面积下与 BB UD 比较见 Pareto。 Stripe/Virtual 中途升 VC、不能按 OD 切开，本轮不做 BB、不进选型。
  4. 推荐：轻载荷（m₀=1）1VC 保底 M3′，压延迟可上 Super-turn（≤2 VC）——计入线延迟同步税后 BB UD 不再支配单表； 重载荷（m₀=13）推 BB UD policy（×3）。 不要选 M0s1 / M5h 换「全覆盖」。

已知局限：只算 dispatch 一次 alltoall； 面积不计牺牲的 PE tile；control 面积按常数、未随 VC 增长； 全量 176 场景扫完后数字以 pg_e2e_pareto.json 为准。

6.4 放宽牺牲预算能否换来全覆盖？

solve_scheme 只在小候选池里找最小基数恢复， 所以对约束更紧的方案会直接判 INFEASIBLE。本小节问的是另一个问题： 如果允许牺牲更多好节点，合法表究竟存不存在。 升级阶梯（solve_scheme_fc）： ① 原 solve_scheme → ② 沿「离故障最近」顺序逐点贪心增长 → ③ 最大健康矩形 → ④ 单行 / 单列（线形拓扑对任何转向模型都合法）。 牺牲 / Te2e 取自全覆盖 e2e（m₀=1，quick 44）。 数据 results/pg_full_cover.json + results/pg_e2e_pareto.json。

7. 指标定义

  • raw / raw_slowdown = mk / mk_golden − 1（与 ring_report 同口径）。 基准是健康 mesh 的 XY alltoall。表中写成百分比，如 +91.0% = 慢 91%。 负值多半来自 A 变小，解读时要对照「牺牲」列。
  • irreg / irregularity_penalty = mk / LB_same_A − 1，其中 LB_same_A = max(minimax_load_lb·m, inj_term, lat_lb)， 在同一存活集合上计算，且与路由无关：
    • minimax_load_lb：对所有轴对齐割 (S,S̄)，S→S̄ 的 |S∩C|·|S̄∩C| 对必须挤过 S 的出边，取 ceil(需求/出边数) 的最大值。任何路由都无法低于它 （健康 8×6 上该值 = 96，正是 XY 的实际负载，说明界是紧的）。
    • lat_lb：按 H/V 加权的最短路直径 + 2·RAMP + (m−1)。
    • inj_term：ceil((A−1)·m / RAMP_BW)。
    因为最忙链路至少要搬 minimax_load_lb·m 个 flit， 所以 mk ≥ LB_same_A 恒成立，irreg 不会为负。 （早期版本分母用的是 XY 随手装填的可达负载，不是下界，故会出现负值。）
  • sacrifice_cost = n_sacrificed / n_originally_good

8. 主要观察

  1. 故障模型与评测范围：主评估 = 预算故障（≤4R+≤8L）； e2e 评有限 VC（Super-turn/Dual/LASH）与分批屏障 1VC； 不考虑多物理 VC 的 Stripe / Virtual / f-ring。
  2. 端到端前沿：见开篇与 §6。中心 hub 同步下 BB UD 常占 VC1 左端； 轻载荷可加 Super-turn。M5h / M0s1 进不了前沿。
  3. 目录外可达性（§2.3）：M3/M6/M7 连通即达（STRUCT=0）； M0s Super-turn 在扫过的空间里同样以断连为主； M0s1 / M5h 会出现 STRUCT 或大量 forced_sac（半环链路端点退休）。 M4 极常见 STRUCT；M10 在散落 ≥3 死节点上会。
  4. §3 预算场景「先牺牲、再 alltoall」：低牺牲档常是 M0s / M3； 重牺牲方案（XY/Rect/half-ring 最坏 A→个位数）makespan 虚低，不进对比。
  5. M1 / M2 / M4（及 East-first）仍排除出 makespan 主表（§2.5）。 预算模型下避障失败或牺牲过重；端到端（§6）里它们垫底。
  6. 保序为构造保证（每对唯一路径 + 确定性 VC）； 区分方案的是避障与无死锁。
  7. M3+LB 几乎无效——同合法集合内局部换路不如换根（M3′）或上多 VC。
  8. Q 与 VC 面积：Q=4 时 Up*/Down* 可慢数倍；VC 线性放大每端口缓冲。
  9. 通信占端到端 70–86%。能分批优先 BB UD；否则 M3′ / Super-turn。
