2. PG 方案详解

实现见 utils/pg_routing.py。所有进入 DES 的表必须同时满足： CDG 无环（无死锁）、每 (src,dst) 唯一路径（保序）、compute 集合连通。 失败时由统一牺牲恢复器禁用额外 good 节点（边界 → 整行/整列 → 矩形屏蔽）。

保序不排斥 VC。保序真正要求的只是「每个 (src,dst) 一条固定路径、 且沿路 VC 序列确定」——只要 VC 是 (src,dst) 的函数而非 per-packet 动态选择， 同一对的包就不会跨 VC 乱序。因此本研究的方案按断环手段分成两大类：

A 类 · 转向限制（1 VC）

mesh 的死锁来自「东→北→西→南→东」这样的通道环。A 类的做法是 删掉环上的某一类转弯，让环无法闭合。

代价：被删的转弯同时也删掉了一批最短路，绕路变长、负载更不均。 洞越大，被迫绕得越远。

成员：M1 XY、M2 Rect-XY、M3 Up*/Down*、M4 Segment。

B 类 · VC 分层（多 VC）

不动路径，而是给通道编层号，规定报文沿路层号只增不减。 环要闭合就必须从高层回到低层，而这被禁止 → 无环。

代价：每层要独立缓冲与 credit，面积随层数放大； 换来的是路径可以贴近最短路。

成员：M5 真 f-ring（4 VC）、M6 LASH / M6b LASH-TOR（1–2 VC）、 M7 条带 dateline（约 5–6 VC）、M9 双向 Up*/Down*（2 VC）、 M10 虚拟规则网格（2 VC）。

2.1 A 类：转向限制

M1 — XY（xy）

思想：坚持维序路由（DOR）：先走完 X，再走 Y；硬件几乎不用改路由逻辑。

路径：对每个 (s,d) 严格按 XY 折线前进；所需 hop 被故障删除则整表失败，进入牺牲恢复。

无死锁：完整矩形上 XY 的 CDG 无环；残图上仍以 CDG 硬校验。

特征：中心/角链路一断极易「穿不过」；恢复时常退化成与 M2 类似的大矩形牺牲。 用于量化「坚持 XY 硬件」要付多少牺牲代价。

M2 — Rect-XY（rect_xy）

思想：不在破损拓扑上绕路，而是裁成仍规则的子矩形，矩形内继续跑 XY。

做法：(1) 标出故障触及的行/列；(2) 在剩余行、列中各取最长连续段，叉成最大轴对齐矩形； (3) 矩形外原计算节点全部记为 forced_sacrificed；(4) 矩形内生成 XY 全表。

无死锁：子矩形上经典 XY，CDG 无环。

特征：牺牲粗、可预测；raw slowdown 常为负是因为参与者变少——应看 irregularity_penalty 与 sacrifice_cost。

M3 — Up*/Down*（updown）

思想：在存活路由图上建 BFS 生成树，用「先上后下」限制转向，保证不规则连通图上的无死锁确定性路由。

做法：(1) 根 = 路由图中度最大节点；(2) label(n) = 到根 BFS 距离， 朝根为 up、离根为 down、同层侧向视为 down；(3) 合法路径 = 若干 up 之后只能 down； (4) 约束下 BFS 取最短合法路径。

无死锁：Up*/Down* 按构造 CDG 无环。

特征：link/node 故障下通常零牺牲即可全表可行，是保住计算规模的主推荐； 路径往往比 XY 更绕、负载更不均，故 raw slowdown 较高。

M3+LB — Up*/Down* + 负载均衡（updown_lb）

在 M3 路径表上后处理：统计有向边 alltoall 对数负载；每轮重排途经最热边的若干 (s,d)， 用负载感知 Dijkstra（边权 ≈ 1+负载）换路；每轮后整表再校验 CDG。失败则回退。

特征：目标是压低最大链路负载；在本 8×6 上对 median makespan 改善通常很小 （Up*/Down* 合法路径集合较窄）。

M4 — Segment / 奇偶转向（segment）

思想：简化 segment-based / odd-even 族：按列带施加不同转向禁令，打破 mesh 环依赖。

转向规则（列段宽 2，seg=(x//2)%2）：直行允许、180° 禁止； 偶段禁 北→东 / 南→西；奇段禁 北→西 / 南→东。路径 = 约束下最短路。

无死锁：完整 mesh 上属奇偶转向模型族；破损后仍 CDG 硬校验，不通则牺牲恢复。

特征：介于 XY 与 Up*/Down*——有时零牺牲，中心故障时常需矩形化。

M4+LB — Segment + 负载均衡（segment_lb）

与 M3+LB 相同流程，起点换成 M4 路径表；同样受转向合法集合限制。

2.2 B 类：VC 分层

M5 — 真 Fault-ring + 4 VC（fault_ring_vc）

思想：Boppana–Chalasani 式容错 e-cube。把所有故障吸收进矩形故障块， 块周围一圈健康节点构成 fault ring；底层仍是原封不动的 XY， 只有撞上块的报文才沿环绕到对面，然后接着走 XY。

四条 VC 怎么分：按相位 × 方向，整条路径上确定，因此保序。

VC0X 相 · 东行VC1X 相 · 西行
VC2Y 相 · 北行VC3Y 相 · 南行

为什么无死锁（可证）：X 相的绕行只会「竖着走」或「朝本报文的 X 方向走」， 所以 VC0 里每条横向通道都朝东。环要闭合就得让 x 回到原点，于是环里不能有横向通道； 剩下纯竖向的环又需要 180° 掉头，而构造上不产生掉头 → VC0 无环（VC1 对称）。 Y 相镜像同理，VC2 内每条竖向通道都朝北。又因为报文只会从 X 相走向 Y 相、绝不回头， 依赖只会从 VC0/VC1 流向 VC2/VC3 → 整张 CDG 无环。

链路故障要付牺牲：块模型里没有「两个活节点之间断了一条链」这种状态， 必须退休一个端点把它变成 1×1 块（右下图）。这是 M5 相对 M3 的固有代价： 纯节点故障零牺牲，纯链路故障牺牲 1–4 个好节点。

固有开销：绕行后要回到原来那一行才继续 XY（图中 (1,2)→(3,2) 再下到 (3,1)）， 这正是换取「X 相严格单调 ⇒ 4 VC 可证无死锁」所付的绕路。

M6 — LASH（lash）

思想：Skeie 等 Layered Shortest Path。每对取一条最短路（可绕障）， 再把全部路径贪心装进尽可能少的 VC 层，使每层 CDG 无环。 路径质量与无死锁解耦——断环靠分层，不靠砍转弯。

做法：(1) 存活路由图上 BFS 最短路；(2) 按路径长度降序，尝试放入已有层， 加入后若该层 CDG 仍无环则收下，否则开新层；(3) 整条路径使用同一层号（常数 VC） → 保序。本 8×6 上实测通常 1–2 层。

与 M5 差别：不强制矩形块、不强制绕回原行；链路故障只需牺牲孤立节点 （度 0），不必把端点做成块。负载往往低于 f-ring。

M6b — LASH-TOR（lash_tor）

思想：在 LASH 上允许路径中途升一层（Trail / Transition On Route）： hop 的 VC 沿路单调不减，从而把本来需要新开一层的路径塞进已有层。

做法：先尝试整路径入单层；失败则枚举分割点，前半段层 lo、后半段层 hi≥lo，分别维护层内 CDG。本 8×6 上 LASH 已是 1–2 层，TOR 收益通常很小。

M7 — 条带 dateline（stripe_vc）

思想：竖向条带 + 边界 dateline。路径优先 XY，不通则最短路； 每水平穿过一条 dateline，VC += 1（沿路单调不减）。

做法：dateline 放在每 2 列边界，并叠加故障列邻边；若稀疏 dateline 下 CDG 仍有环，则加密到每个列边界。VC 数 ≈ 跨越数+1（本网格约 5–6）。

特征：实现极简、路径贴近最短；VC 数高于 LASH/f-ring，缓冲面积更大。

M9 — 双向 Up*/Down*（dual_updown）

思想：VC0 跑经典 Up*/Down*（先上后下），VC1 跑对称的 Down*/Up*（先下后上）； 每对选更短的那条，整路径固定在所选 VC → 保序。

无死锁：两套规则各自 CDG 无环，且路径不跨 VC 混用。

特征：固定 2 VC，实现比 LASH 简单；路径短于单层 Up*/Down*，但通常仍长于最短路族。

M10 — 虚拟规则网格（virtual_mesh）

思想：上层仍看完整 8×6 逻辑 mesh 与 XY；物理上缺失的逻辑边用固定最短绕路 替换。逻辑路径遇洞则跳过死节点并桥接。

VC：到达目的列之前的物理 hop → VC0（逻辑 X 相），之后 → VC1（逻辑 Y 相）。

特征：软件映射可保持规则 mesh；链路故障友好；大洞时绕路变长，CDG 硬校验。

3. 每场景最优方案选择

判据按用户口径：先看牺牲节点数，再看 makespan。这也让比较更公平—— 牺牲数相同意味着参与 alltoall 的节点数 A 相同，makespan 才可直接对比 （A 变小会让 makespan 无偿变好，见 M2）。 「Pareto 备选」列出所有非受支配的 (牺牲, makespan) 组合： 若愿意多牺牲若干节点换更快，就从这里挑。

表头 raw / irreg 百分比含义：

  • raw（raw_slowdown = mk / mk_golden − 1）：相对健康 8×6 XY golden 的变慢比例。 例如 +20.0% 表示 makespan 比 golden 长 20%； −30.0% 表示比 golden 还短——通常因为牺牲后参与者 A 变少、总流量按 A² 下降， 不是路由变好。跨场景比「路由质量」时不要只看 raw。
  • irreg（irregularity_penalty = mk / LB_same_A − 1）：相对同一存活集合 A 上与路由无关的真下界（割下界带宽项 / 注入 / 延迟三者取 max）的额外开销。 例如 +9.8% 表示在「这些节点无论怎么路由都至少要跑这么久」之上，又慢了约 10%—— 来自绕路、负载不均、死锁约束等。比 raw 更适合比较路由质量，且恒 ≥ 0。
  • 百分比由比值减 1 再 ×100 显示。raw 可能为负（牺牲后 A 变小所致）；irreg 不会为负。

6. 指标定义

  • raw / raw_slowdown = mk / mk_golden − 1（与 ring_report 同口径）。 基准是健康 mesh 的 XY alltoall。表中写成百分比，如 +91.0% = 慢 91%。 负值多半来自 A 变小，解读时要对照「牺牲」列。
  • irreg / irregularity_penalty = mk / LB_same_A − 1，其中 LB_same_A = max(minimax_load_lb·m, inj_term, lat_lb)， 在同一存活集合上计算，且与路由无关：
    • minimax_load_lb：对所有轴对齐割 (S,S̄)，S→S̄ 的 |S∩C|·|S̄∩C| 对必须挤过 S 的出边，取 ceil(需求/出边数) 的最大值。任何路由都无法低于它 （健康 8×6 上该值 = 96，正是 XY 的实际负载，说明界是紧的）。
    • lat_lb：按 H/V 加权的最短路直径 + 2·RAMP + (m−1)。
    • inj_term：ceil((A−1)·m / RAMP_BW)。
    因为最忙链路至少要搬 minimax_load_lb·m 个 flit， 所以 mk ≥ LB_same_A 恒成立，irreg 不会为负。 （早期版本分母用的是 XY 随手装填的可达负载，不是下界，故会出现负值。）
  • sacrifice_cost = n_sacrificed / n_originally_good

7. 主要观察

  1. 全 B 类就位后，按「牺牲→makespan」仍几乎全是 M7 Stripe （约 70/72 场）。dead·m=1 中位 mk：Stripe 194 < Virtual 240 < f-ring 248 < LASH/TOR 257 < Dual-UD 342 ≈ Up*/Down* 344。
  2. M6b LASH-TOR 与 M6 中位完全相同（本网格 LASH 已是 1–2 层，升层无额外收益）。 M9 Dual-UD 相对 M3 几乎无改善。 M10 Virtual mesh 以 2 VC 夹在 f-ring 与 LASH 之间，适合要保留规则映射的场景。
  3. 链路故障：M5 须退休端点；LASH/Stripe/Virtual 通常只需拿掉孤立点， 且中心链路可零牺牲。
  4. 按「先牺牲、再 makespan」：M7 Stripe 几乎通吃 （dead/transit × m=1/5 合计约 70/72 场）。仅个别场次 M5/M6 并列或略胜。 代价是 5–6 VC。若看 Pareto 上「同牺牲、更少 VC」，常落到 M6 LASH。
