# iSLIP-2D：两种 fabric、两套冲突判据（8×6）

**几何：** 8×6，48 节点；H=7，V=9；RAMP=2，RAMP_BW=2
**Fabric A：** 2D mesh，164 条有向链路，路由器为全 crossbar
**Fabric B：** 维度切片 2D 无缓冲环，6 行环×8 + 8 列环×6，**192 条有向链路**（金属 96/82 = **1.17×** mesh），环站无缓冲、**每个节点都是行/列环之间的桥**
**判据：** mesh 用 **D-M**（3 子句）/ 环用 **D-R**（5 子句），**两套不可通用**，交叉误用代价已量化
**授权：** 每源每轮 **1 条 request（残余 VOQ 位图）→ 1 条宽 grant**，未授予的 VOQ 下轮重新带出；request/grant 时延统一为常数 `T_rtt`
**两类实验：** 批量 makespan（`results/islip2d_8x6.json`）+ 开环稳态注入率扫描（`results/load_sweep_8x6.json`）
**验证：** `results/verify_islip2d_8x6.json`，全部检查项可执行、失败即命名具体量
**基线：** `mesh_base`（VC + 信用反压 + 输入队列 iSLIP）/ `ring_base`（E-tag / I-tag + 偏转，按 HPCA'22 海思论文与 HiRD 同源机制重建）

## 0. 一页结论

1. **区间冲突域不是优化项，是这套方案能不能工作的分界线。** 稳态 λ=0.5，mesh 集中式接受吞吐 **0.486（interval）vs 0.109（free_at）= 4.5×**，环 **0.496 vs 0.145 = 3.4×**。
   原因是刚性授权的起始时刻取路径上各资源要求的**最大值**，而 `free_at` 提交时会把**整条路径上每个资源**的前沿都推到那个最大值——一条拥塞链路把自己的滞后**输出**给它碰到的所有链路，再逐跳扩散。实测链路利用率停在 22%，而所有前沿都被顶到地平线。
   代价也必须一起说：区间表是集中式仲裁器**面积的主体**（mesh 99,840 / 环 184,320 bit，占总量 96%/97%）。

2. **两套判据确实不可通用，但「不安全」和「不可达」是两件事。** 环上链路互不相交的 VOQ 对里仍有 **1.08%** 在上/下环端口冲突（细分 board-board 79.5% / leave-leave 11.6% / board-leave 8.8%）——纯链路判据**不安全**。
   纯 R1 判据把可并发集合从 61.8 高估到 93.8（**1.52×**）——**判据宽松度**的高估。
   但轮次代价很小：`ports=1` 69 轮 → `ports=2` 65 轮（−5.8%）。**稳态下端口根本不绑定**（端口 λ\*=1.119 vs 链路 λ\*=0.783）。

3. **环相对 mesh 的优势存在，但只在 σ=1 口径下。** 批量 **69 vs 110 轮（1.59×）**，稳态 λ\* **0.75 vs 0.45～0.50（约 1.6×）**。
   **金属恒定 σ=2 下环反而更差**：等效饱和 0.783/2 = 0.39 < mesh 的 0.49。σ=1/σ=2 双口径是必须的，不是可选的。

4. **iSLIP 的指针纪律在 mesh 上要付 13% 轮次代价。** 同一实现下 `iters=0`（纯贪心补齐）**97 轮 = 1.01× 割界**，`iters=1`（两级指针 grant/accept）**110 轮 = 1.15×**，`iters=2` 回到 103。
   全路径一致授予的比例只有 **23.1%**——mesh 上一条 VOQ 要它路径上**所有**链路同时同意，这是分布式匹配在路径资源上的固有低效，多迭代能买回一半。

5. **集中式对无缓冲环不是「更快」，是「可行」。** R4 要求转环零松弛，分布式环站必须预知另一条环未来的时隙占用——做不到，只能加缓冲、偏转或绕圈。
   E-tag/I-tag 基线为此付出 **198,528 bit** 的分布式存储（桥 FIFO 49,152 + 预留 Tx 12,288 + Eject 队列 24,576 + 目的端重组 98,304 + 阈值计数器与 bypass），而集中式把这些**全部删除**。

6. **但环上「集中化省面积」的说法必须撤回。** 集中式环仲裁器（区间域）**189,528 bit** ≈ 基线的 198,528 bit，**净省 9,000 bit，比值 1.05×——基本打平**。
   mesh 上才是真省：基线 616,560 bit（信用缓冲按线延迟定尺寸）vs 集中式 103,532 bit = **5.96×**。
   环上集中化换到的是**吞吐（1.36×）、有界延迟（p99 157 vs 1445）与删掉死锁/饿死机制**，不是面积。

7. **`ring_base` 不会死锁，而且救它的不是 Swap Rule。** 固定维序下所有转向都是行→列，桥永远看不到互相转向，**Swap Rule 恒不触发（0 次，开关结果逐位相同）**；只有 `mixed` 维序下才会触发（74 次）。
   即便在 `mixed` + `fifo_depth=1` + 时隙稀缺模式下**关掉 Swap Rule 也不死锁**：每节点每环向每拍最多到达 1 个 flit，转不了的 flit 其续行段**总是空的**，偏转无条件可用。
   无缓冲偏转环的失效模式是**活锁与延迟长尾**，不是死锁。这与计划的预期相反，按「以重跑为准」记录。

8. **偏转确实消耗环带宽并造成吞吐回落，这条可 falsify 的预测成立。** `ring_base` 稳态 λ=0.55 接受 0.5475（稳定）→ λ=0.8 接受 0.5273（**回落**），p99 从 85 涨到 2080；
   `ring_islip2d` 干净地在 λ\*=0.75 平台化，p99 = 157。**乱序 165 次、重组缓冲峰值 58 flit**——基线必须有重组缓冲，集中式靠 R5 删掉它。

9. **`mesh_base` 的缓冲深度必须扫，否则把胜负判反。** 信用往返 ≈ 2×(7~9) ≈ 15~19 拍。峰值接受吞吐：`buf=4` **0.078**、`buf=8` **0.199**、`buf=20` **0.396**。
   只报浅缓冲会低估基线 **5×**；只有 `buf ≥ RTT` 时基线才贴近 0.490 解析锚点。这同时正是无缓冲 + 集中式的卖点：**完全不付 RTT 缓冲税**。

10. **RTT 吃掉全部流水收益的临界点：mesh ≈ 65 拍、环 ≈ 46 拍（`pipeline_depth=1`）。** 环更敏感，因为它的数据跨度只有 mesh 的一半，同样的控制时延占比更大。
    `pipeline_depth=2` 就把 `T_rtt=64` 的 makespan 从 7074 拉回 4427；深度 ∞ 时 RTT 只贡献 +64 拍。**控制环流水是必须的，深度 2 已经够。**

11. **ROMM 的判据要分两层说。** 「ROMM 有价值 ⟺ `max_e load > 割界`」对**峰值负载**成立（无余量的 `alltoall`/`halfxhalf`/`permutation` 负载增益恒为 0），
    但对**轮次**不成立：`permutation` 负载正好贴界（3 = 3）却仍从 4 轮降到 3 轮（−25%），因为该尺度下绑定约束是冲突图的**打包性**而非峰值负载。
    有余量时增益显著：`transpose` 7→4（−43%）、`hotspot_any` 40→27（−33%）、`cornerAtoB` 8→6（−25%）。**随机 ROMM 全面劣于平衡 ROMM**（`alltoall` 110→119 轮）。

12. **保序不变量在两个 fabric 上形态不同。** mesh 矩形内 ROMM **时延不变**（14,560 组抽样，跳数与线延迟失配 **0**）⇒ 换路仍严格保序；
    环上最小路径**也**时延不变（2,256 对，线延迟跨度 0），但一旦放开到非最小路径就不成立，故 R5 仍要求静态定路。三种 mesh 路径模式实测乱序均为 **0**。

13. **过载区的峰值接受吞吐会超过解析锚点，这不是 bug，比较口径必须用 λ\*。** `mesh_islip2d` 峰值 0.533 > 锚点 0.490。逐链路实测给出机理：λ=0.48（稳定）时最热链路利用率 **0.965**，与「混合比均匀」的预测 0.968 吻合，锚点严格绑定；λ=1.0（过载）时它掉到 **0.804**，而均匀混合比本会要求 1.089（不可能）——逐 VOQ 反压使 CA 只授权当下放得下的流，接受的混合比**漂离热割 26%**，聚合吞吐因此抬高。平均跳数只漂 3.0%，所以这是热割回避而非「只发近包」。**锚点约束稳定区，不约束过载峰值。**

## 1. 共同前提：什么叫一次「被授权的传输」

两个 fabric 共用的只有**授权对象**与**零缓冲的刚性含义**，冲突判据本身分开定义。

一次授权 `r = (VOQ(s,d), t0, route, m, σ)`：源 s 在 t0 起、沿 `route` 连续发出 m 个 flit，每 flit 占链路 σ 拍。**零缓冲 = 全路径无松弛**：整条路径上只有 `t0` 一个自由度，任何中间节点都不得停留（不是「每跳一个自由度」）。因此 `r` 的时空印记完全由 `t0` 与 `route` 决定，可预先计算、可作为区间做冲突检查。

`pref_route(x)` 记为「从 t0 到资源 x 开始被占用」的累计线延迟。占用区间统一写作**左闭右开**区间（与 `rg-noc-8x6.md` §2.2 同一记法）：

```
occ_r(x) = [ t0 + pref_route(x),  t0 + pref_route(x) + dur(x) )
```

右端开是有语义的：资源被占用的拍是 `t0+pref` 至 `t0+pref+dur−1`，故下一次传输**可以恰好在** `t0+pref+dur` 起始。若写成闭区间会禁止背靠背复用，每资源每次传输白付 1 拍。

实现上这个区间语义直接落成位图：`rg_steady_des._SlotMap` 为每个资源、每个 server 维护一条随时间滑动的占用位向量，判定「整条路径在 t0 是否可行」就是把各资源的可用向量按各自 `pref` 右移后**按位与**，取最低置位即最早可行 t0。硬件里这就是那张区间表。

> **一处必须点名的实现陷阱。** 容量 >1 的资源（ramp 容量 `RAMP_BW`、环端口容量 `board_ports`/`leave_ports`）上，「存在某 server 在整段 `m·σ` 内空闲」与「每一拍都存在某 server 空闲」**不是同一个命题**：后者允许不同拍由不同 server 覆盖，而一次传输用不了这种时隙。`m·σ = 1` 时两者恰好等价，所以这个错误只在多拍包上现形——它是被 `reserve()` 的容量断言抓出来的，不是靠看代码看出来的。这也是为什么容量断言留在提交路径上而不是放进单独的检查过程。

## 2. 定义 D-M：2D mesh 上的冲突

**资源集合**：164 条有向链路（8×6 mesh，无绕回）+ 48 个注入 ramp + 48 个弹出 ramp。路由器是全 crossbar，**不把交叉点/端口当稀缺资源**（沿用仓库既有模型）。

**路径形态**：`route = (v0=s, …, vh=d)`，XY 时为 L 形，ROMM 时为两段最小折线；`h ≤ (MX−1)+(MY−1) = 12`。链路时延 `lat(e) ∈ {H=7, V=9}`。

**D-M 冲突定义（三条子句，全部满足才叫无冲突）**

| 子句 | 内容 |
|---|---|
| **M1 链路互斥** | 对任意有向链路 e 与任意两次授权 `r1 ≠ r2`，若 `e ∈ route(r1) ∩ route(r2)`，则 `occ_{r1}(e) ∩ occ_{r2}(e) = ∅`，其中 `dur(e) = m·σ` |
| **M2 Ramp 容量** | 任一节点、任一拍，注入并发数 ≤ `RAMP_BW·σ`，弹出并发数 ≤ `RAMP_BW·σ` |
| **M3 同 VOQ 串行** | 同一 `(s,d)` 的各次授权 `t0` 全序且占用不重叠（保序所需，非带宽所需） |

**结构性质（决定算法形态）**

- 一次授权占用的是 **164 条链路中任意一个 ≤12 元子集**（L 形/折线），冲突检验 = 集合交 + 区间交。冲突图是**任意 L 形的交图**，无良好结构 ⇒ 贪心无逼近保证（实测仍贴界，见 §5）。
- **共享链路 ≠ 冲突**：`pref` 逐链路不同，两条路径可以「错时穿过」同一链路。轮/相位模型（同轮共享 t0）会把这条自由度丢掉——这正是 `conflict_domain=free_at` 与 `interval` 的差别，而实测这条自由度值 4.5×（§8）。
- 下界是**割界**：`alltoall` 的 `max_e load(e) = 96`，见证为 `x=4` 处的东向中切——左半 24 源 × 右半 24 目的 = 576 条流，中切同向仅 6 条链路，`⌈576/6⌉ = 96`。XY 恰好达到该界（实测 `max_load = 96 = cut_bound`）。

**crossbar 判据在 D-M 下双向失效**（沿用探路口径的结论；本轮重跑聚焦环上同类量，见 §4）：「src≠src ∧ dst≠dst」的 VOQ 对仍可能共享链路（判据**不安全**），而 crossbar 恒判冲突的「同源不同 dst」在 mesh 上大量实际无冲突（判据**过严**）。

## 3. 定义 D-R：2D 无缓冲环上的冲突

**资源集合（与 D-M 的关键差异在第 3 类）**

1. **192 条有向环链路**。k 个节点的环有 **k** 条链路（含绕回），故 6 条行环各 8 条、8 条列环各 6 条 ⇒ 48 + 48 = **96 条无向** ⇒ ×2 方向 = **192 条有向**。同一无向链路的两个方向是**两个独立资源**（同环反向弧永不争用）。
   与 mesh 的差额恰是绕回链路：mesh 为 7×6 + 5×8 = **82 无向**（164 有向），每行每列各加 1 条绕回 ⇒ +6+8 = 14 ⇒ 96 无向、192 有向，金属比 96/82 = **1.1707×**（实测 `audit()`）。
   **该链路集与仓库现有折叠 2D torus 完全相同**（实测 `assert_same_links_as_torus`：96 vs 96，双向差集均为 0）。两者差别**只在节点**：torus 路由器是带缓冲的全 crossbar，环站无缓冲、插入/抽取点有限、转向须下环再上环。故环直接继承 torus 的金属记账（折叠线长 ×2 ⇒ σ=2），σ=1 与 σ=2 双口径是沿用既有纪律而非新增假设。
2. 48 个注入 ramp + 48 个弹出 ramp（同 M2）。
3. **上环/下环端口（mesh 无此类）**：每节点对它所属的**每条环**各有 `board_ports` 个插入点、`leave_ports` 个抽取点（默认各 1）。节点 n 同属 1 条行环与 1 条列环 ⇒ 2 插入 + 2 抽取。环站没有 crossbar，插入/抽取点是**真实稀缺资源**。

**路径形态（两相 + 刚性转环）**：`route = (行相弧 A_row on R_{y_s}, 转环节点 t, 列相弧 A_col on C_{x_d})`（RC 序；CR 序对调）。弧是环上**连续**一段，由 `(环 id, 方向 δ, 起止)` 决定，可绕回。**转环无缓冲 ⇒ 列相起始时刻严格等于行相到达时刻 + `T_turn`**，没有松弛。

**D-R 冲突定义（五条子句）**

| 子句 | 内容 |
|---|---|
| **R1 环链路互斥** | 同 M1，但资源是 192 条有向环链路，占用形态是弧。反向弧永不冲突 |
| **R2 上环互斥** | 任一节点 n、任一环、任一拍，boarding 数 ≤ `board_ports` |
| **R3 下环互斥** | 任一节点 n、任一环、任一拍，leaving 数 ≤ `leave_ports`。**目的地弹出与转环下环共用抽取点** |
| **R4 转环原子性** | 一次转环在**同一拍**同时消耗行环的一个抽取点与列环的一个插入点；两相时刻由 `T_turn` 刚性绑定，不得插入等待 |
| **R5 同 VOQ 串行 + 路径静态固定** | 同 `(s,d)` 的授权 `t0` 全序且不重叠，**且必须使用同一条固定路径** |

实现上 R4 不需要独立子句检查：转环的 leave 偏移与 board 偏移在同一个 footprint 里相对 t0 固定，只要 t0 唯一就自动对齐。独立复核器仍逐条验证五个子句，实测 `max_turn_residency = 0`（拐点零驻留）。

**空间复用是判据的一部分（同一 fabric 两种定义）**

「同一行的 8 个节点共用一条物理双向行环」与「192 条有向链路」并不矛盾：**一条环由 8 段前向 + 8 段反向的相邻节点线段构成**（7 段近邻 + 1 段绕回），192 是全网**线段**计数。争议点不是布线，而是**仲裁把谁当互斥单位**：

| `spatial_reuse` | 互斥体数 | 链路下界 | 实测轮次 | 相对 |
|---|---|---|---|---|
| `arc`（默认） | **192**（弧/线段） | 60 | **69** | 1× |
| `whole_ring` | **28**（14 环 × 2 方向） | 192 | **195** | **2.83×** |

`whole_ring` 的 192 有闭式来源：单条行环单方向 = 8 源 × 4 个顺时针可达列 × 6 行 = 192 条流全部串行。它便宜到一次标量比较，但已劣于 mesh 的 110 轮。**环的带宽优势完全来自空间复用，一旦按共享介质仲裁就不复存在。**

**结构性质**

- 每条环上的占用是**连续弧** ⇒ 单环冲突图是**圆弧图**。首次适配贪心在圆弧图上有 2× 保证 ⇒「按弧长降序」对应经典最优序。实测跨度确实比 mesh 大：`arc_desc` **69** vs `arc_asc` **79** vs `random` **79** vs `flowid` **81**（最好/最差 1.17×），而 mesh 上五种规则落在 103～114（1.11×）。
- **R2/R3/R4 不被 R1 蕴含**，这是环独有的。凡「两条弧在同一节点、同一环相遇但最后/第一条链路不同」的情形（双向汇聚、或转环与本地弹出撞在同一抽取点）链路判据都看不到。
- 意外结果：`pressure`（按资源压力）在环上是最好的规则（**65** 轮），比理论最优序 `arc_desc` 再好 5.8%。圆弧图的最优序论证只覆盖单环，而这里每条流跨两条环加两个端口，单环最优不等于全局最优。

## 4. 为什么两套判据不能通用（量化）

| 论断 | 量 | 数值 | 来源 |
|---|---|---|---|
| 把纯链路判据搬到环上**不安全** | 链路不相交却在端口冲突的比例 | **1.08%** | 40,000 组抽样 |
| ↑ 冲突类型细分 | board-board / leave-leave / board-leave | **79.5% / 11.6% / 8.8%** | 同上 |
| 纯链路判据**高估并发度** | 贪心最大无冲突集 R1-only vs R1+R2+R3 | **93.8 → 61.8（1.52×）** | 20 次试验均值 |
| 但**轮次代价很小** | `ports=1` → `ports=2` | **69 → 65（−5.8%）** | 批量 |

## 5. Part A：`islip2d_mesh`

**A｜同步时隙 request–grant 循环。** 统一 RTT `T_rtt`。轮 r：① 每源发**一条** request，payload = **残余 VOQ 位图**（47 bit）；② CA 对 48 条 request 做一次匹配，产出一个满足 D-M 的授权集；③ 每源收到**一条**宽 grant（VOQ 索引 + t0）；**未授予的 VOQ 在下轮 request 中重新带出**；④ 轮 r+1 的 request 与轮 r 的数据流水重叠。

实测控制面每轮 **82.3 条**消息（上界 2×48 = 96，空位图的源不发），全程 9,050 条。对照旧口径「一条 request = 一条 VOQ」的 2×2256 = **4,512 条一次性汇聚**，降低 **50×**，且**与积压无关**——这是残余位图格式换来的，不是靠减少工作量。

**B｜`grants_per_src`。** `alltoall`、`interval` 域：

| `grants_per_src` | 轮次 | / 割界 | 数据跨度 | 每轮流数 |
|---|---|---|---|---|
| 1（按定义） | **111** | 1.156 | 150 | 20.3 |
| 2（= `RAMP_BW`） | **110** | 1.146 | 145 | 20.5 |

「一 request 一 grant」的代价只有 **0.9%**——远小于探路预期的 4.2%。因为绑定约束是链路，不是源端 ramp；放宽源端并不解开链路。**这个旋钮可以按定义取 1，不必为它增加 grant 宽度。**

**C｜两级指针的代价必须明说：13%。** grant 指针每有向链路一个（`g_e`，over 48 源，6 bit×164 = 984 bit）；accept 指针每源一个（`a_s`，over 48 dst，6 bit×48 = 288 bit）。在**全路径一致授予**的 VOQ 中按 `a_s` 接受。

| `iters` | 轮次 | / 割界 | 全路径一致率 |
|---|---|---|---|
| **0**（纯贪心补齐，无指针相） | **97** | **1.01** | 0 |
| 1 | 110 | 1.146 | 23.1% |
| 2 | 103 | 1.073 | 12.9% |
| 4 | 103 | 1.073 | 19.2% |

一致率只有 **23.1%**：mesh 上一条 VOQ 要它路径上**所有**链路同时同意，而交叉开关上只要 1 个输出端口同意。这正面回答了「为什么 mesh 需要集中调度」——不是工程偷懒，是分布式匹配在路径资源上不收敛。而 `iters=0` 贴到 1.01× 割界说明：**在集中式全可见的前提下，指针纪律买到的是公平性与去同步，不是轮次**；要轮次就把迭代加到 2。

**D｜补齐顺序只是二阶效应。** `hops_desc` / `hops_asc` / `pressure` 均 **110**，`random` **103**，`flowid` **114**（跨度 1.11×）。跳数降序并不优于其他静态序——与环上 1.17× 的跨度对比，说明 mesh 的 L 形交图没有可利用的排序结构。对照既有算法：`latin_mesh` **99**（1.03×，离线 ROM）、`islip_mesh` **156**（1.63×）、`greedy_ff` / `bcfs` 为流水型无轮次概念（数据跨度 1971 / 1990）。

**E｜`conflict_domain` 在批量口径下不改轮次，但改 26× 的跨度。**

| 域 | 轮次 | 数据跨度 | grant 平均等待 |
|---|---|---|---|
| `free_at` | 110 | **3831** | 1776.6 |
| `interval` | 110 | **145** | 45.5 |

轮次相同（轮次由链路负载决定），但 `free_at` 把每轮的起始时刻串行化到前沿之后，跨度被拉长 26×。这条自由度在稳态口径下直接变成 4.5× 的吞吐差（§8）。

**F｜`path_mode`（ROMM）：判据要分负载与轮次两层。**

| pattern | XY 负载 | 割界 | 有余量 | ROMM 负载 | 轮次 XY→ROMM | 轮次增益 |
|---|---|---|---|---|---|---|
| `alltoall` | 96 | 96 | 否 | 96 | 110 → 110 | 0 |
| `halfxhalf` | 96 | 96 | 否 | 96 | 100 → 100 | 0 |
| `permutation` | 3 | 3 | 否 | 3 | 4 → **3** | **−25%** |

## 6. 基线：`ring_base`（E-tag / I-tag + 偏转）

**⚠ 与 D-R 不是同一类东西。** D-R 是**排程谓词**（CA 事前判定「这批授权是否无冲突」）；E-tag/I-tag 是**反应式逐拍策略**（事中靠优先级与偏转化解冲突，从不做全局无冲突保证）。两者不能作为「定义」对比，只能比**结果**（吞吐/延迟/序/面积）。

**逐拍规则**（按 HPCA'22 海思论文，细粒度时序按 HiRD 同源机制补齐）

- 环内传输**永远优先**：已在环上的 flit 不停留、不被缓冲，逐拍前进。实测该不变量零违例（`n_inring_blocked = 0`，四种配置）。
- **上环（I-tag）**：源只能插入**空时隙**。连续抢不到时 `I-tag` 置起，为饿死节点**预留**一个空时隙（抑制上游注入），阈值 `T_inj` 后生效。
- **下环 / 转环（E-tag）**：转环需要目标环的 **transfer FIFO** 有空位，没空位则**偏转**——flit 绕环一圈后重试。`E-tag` 在饿死超过 `T_xfer` 后为该 flit 预留 FIFO 槽位。
- **Swap Rule**：桥两侧刚到达的 flit **互相要转到对方环**时二者直接交换、绕过 FIFO（需 bypass 通路）。
- **死锁检测与恢复**：cross point 连续注入失败超阈值 ⇒ 判定 Eject Queue 与可用 Tx buffer 全满 ⇒ 进入 resolution mode，把**预留 Tx buffer** 让给死锁 flit。
- **交付乱序**：偏转与 Swap 都造成乱序，故需目的端**重组缓冲**。

**三条与计划预期相反的实测结论**

1. **固定维序下 Swap Rule 恒不触发。** 所有转向都是行→列，桥永远看不到互相转向，故 Swap 的前提条件不可满足：实测 **0 次**，开/关结果逐位相同。只有 `dim_order=mixed`（层级环的配置）下才触发，**74 次**。
2. **关掉 Swap Rule 也不死锁**，即便在 `mixed` + `fifo_depth=1` + 时隙稀缺模式下。原因是结构性的：每节点每环向每拍最多到达 **1 个** flit，所以转不了的 flit 其**续行段总是空的**，偏转无条件可用。死锁检测器的阈值条件（FIFO 阻塞 + Eject 队列满）确实会触发，但系统自行恢复，那些触发是**假阳性**。
3. 因此**无缓冲偏转环的失效模式是活锁与延迟长尾，不是死锁**；兜住它的是 E-tag/I-tag 的饿死保证，不是 Swap Rule。要复现真死锁需要一个能**阻塞环内 flit** 的站点——多 flit 包保持连续、或桥是环层之间的唯一通路。维度切片 2D 环 + 单 flit 偏转都不满足，故「集中化消掉了死锁硬件」这一条必须**收窄**为「消掉了那套为死锁准备的机制与它的面积，而不是消掉了一个已证实会发生的死锁」。

**饿死确有界**：`max_inj_starve` 在 `T_inj ∈ {8,16,64}` 下分别为 119 / 56 / 112 拍——有界且量级远小于仿真长度。**乱序确实发生**：165 次，重组缓冲峰值占用 **58 flit**，这直接标定了基线必须配的 `reasm_depth`。

**因此基线不是「零缓冲」**：环内无缓冲，但**每个桥有 transfer FIFO + 预留 Tx buffer + Eject Queue，目的端有重组缓冲**。在维度切片 2D 环里**每个节点都是行环/列环之间的桥**（实测 `n_bridges = 48`），故这笔开销是**逐节点**的，不像 HiRD 只落在少数 bridge router 上。这个差异放大了基线开销，是本报告与原提案的口径差别，必须随数一起引用。

## 7. Part B：`islip2d_ring` 与集中化的必要性

**算法**：资源与冲突严格按 **D-R**，五条子句都进独立复核器。grant = 每条**环-方向**按弧起点序 RR 授予一个请求者（28 个仲裁单元，而 mesh 需要 164 个）；accept = 每源按 `a_s` 接受，且只接受行相与列相**同时可行且按 R4 对齐**的 VOQ。

| `ring_path_mode` | `g` | 轮次 | 链路下界 | / 下界 | 数据跨度 |
|---|---|---|---|---|---|
| `fixed`（RC + 最短方向） | 1 | **67** | 60 | 1.117 | 2009 |
| `fixed` | 2 | 69 | 60 | 1.150 | 1941 |
| `balanced`（方向×维序四选一，离线平衡） | 1 | 64 | 49 | 1.306 | 1976 |
| `balanced` | 2 | **63** | 49 | 1.286 | 1952 |
| `dyn`（每 grant 重选） | 2 | 65 | 56 | 1.161 | 2047 |

`balanced` 把下界从 60 压到 49，但实现只吃到 63——离下界更远（1.29× vs 1.12×）。**下界改善 18% 只换到轮次改善 6%**：平衡后的路径集更难打包。`balanced` 必须静态固定以满足 R5。

**端口与空间复用**

| `board_ports` / `leave_ports` | 轮次 | 数据跨度 |
|---|---|---|
| 1 / 1 | 69 | 1941 |
| 1 / 2 | 67 | 1849 |
| 2 / 1 | 67 | 1876 |
| 2 / 2 | **65** | 1811 |

端口翻倍只值 **5.8%**（69→65）。结合 §4 的「稳态端口不绑定」（λ\* 1.119 vs 0.783），结论是：**上/下环端口不是环的首要架构旋钮**，探路阶段基于 2.4× 并发差距做出的判断在可达性能上不成立。首要旋钮是 `spatial_reuse`（2.83×）与 `conflict_domain`（稳态 3.4×）。

**全环仲裁的代价**：`whole_ring` 195 轮 vs `arc` 69 轮 = **2.83×**，每轮流数从 32.7 掉到 11.6。这证明弧式仲裁的复杂度是必要的。

**集中化的核心论点（为什么是「可行」而不是「更快」）**

R4 要求转环零松弛：列相起始时刻严格等于行相到达 + `T_turn`。分布式环站要满足它，必须**预知另一条环未来的时隙占用**——做不到。于是分布式实现只有三条退路：在拐点加缓冲（就是 transfer FIFO）、绕一圈重试（偏转，消耗带宽）、或活锁。**集中式上/下环仲裁使无缓冲 2D 环按构造成立。**

集中式逐条消掉的硬件（面积见 §10）：

| 基线机制 | 集中式为何不需要 | 基线面积 |
|---|---|---|
| 桥 transfer FIFO（48 桥 × 2 环） | R4 精确对齐，转环零松弛 | 49,152 bit |
| 预留 Tx buffer | 同上 | 12,288 bit |
| Eject Queue | 弹出时刻由 t0 决定，不需缓冲 | 24,576 bit |
| 目的端重组缓冲 | **R5 保序**，永不乱序 | 98,304 bit |
| 注入/转移保证阈值计数器 + tag 状态 | CA 授权即公平 | 1,920 bit |
| Swap Rule + bypass 数据通路 | 按构造无需化解冲突 | 12,288 bit |
| 死锁检测 + resolution mode | 按构造不可能死锁（但见 §6 的收窄） | — |
| **合计** | | **198,528 bit** |
| 代价：中央仲裁器（区间域） | | **189,528 bit** |

净账 **−9,000 bit（1.05×）**——环上集中化基本是**面积中性**的，它换来的是可行性与保序，不是面积。mesh 侧则是 **5.96×**（消掉 616,560 bit 的 VC 缓冲，加回 103,532 bit 仲裁器），因为有缓冲 mesh 的存储本来就重。

## 8. 稳态注入率扫描：四配置头对头

**口径**：开环、源端无限队列、`alltoall`（每节点每拍以 λ 生成一个包，目的均匀取自其余 47 个）、warmup 1200 + measure 5000 拍、`buf_depth=20`（覆盖 CBFC 的 RTT）。λ\* 定义为**最大仍判稳定**的 λ（队列斜率 < 0.002 且接受比 ≥ 0.98）。

### 8.1 主曲线

| 配置 | λ\* | 解析锚点 | 贴界 | 峰值接受 | 低载 p50 | λ\* 处 p50 | 高载 p99 | 饱和后行为 |
|---|---|---|---|---|---|---|---|---|
| `mesh_base` | **0.40** | 0.490 | 82% | 0.406 | 38 | 46 | 5592 | **回落 42%**（0.406 → 0.236） |
| `mesh_islip2d` | **0.48** | 0.490 | **98%** | 0.533 | 54 | 70 | 4684 | **平台化，零回落** |
| `ring_base` | **0.55** | 0.783 | 70% | 0.573 | **27** | 36 | 3129 | **回落 16%**（0.573 → 0.479） |
| `ring_islip2d` | **0.75** | 0.783 | **96%** | 0.830 | 46 | 94 | 2986 | **平台化，零回落** |

三条结论，每条都能单独falsify：

1. **集中式贴界，分布式不贴界。** 集中式 λ\* 到解析锚点的 96～98%；两个分布式基线只有 70～82%。缺口的来源不同：`mesh_base` 是信用反压 + HOL 阻塞，`ring_base` 是**偏转消耗环带宽**（每次偏转多占一整圈时隙）。
2. **饱和后的分野正如预测。** 两个基线在过载区**接受吞吐回落**（mesh −42%、环 −16%）——这是拥塞崩溃，因为反压/偏转本身要消耗被争用的资源。两个集中式配置**单调平台化、零回落**：CA 不会授权它放不下的传输，过载只体现为源端积压。计划里这条是「可预期且可falsify」的分野，实测成立。
3. **公平性差一个量级。** λ\* 附近吞吐离散度 CV：`ring_islip2d` **0.0075** vs `ring_base` **0.0119**；过载区差距拉大到 `mesh_islip2d` 0.456 vs `mesh_base` **0.853**。基线的 I-tag/E-tag 饿死保证有界但粗；CA 的两级指针直接给出接近理想的公平。

### 8.2 「峰值接受超过解析锚点」不是 bug，是混合比漂移

`mesh_islip2d` 峰值接受 0.533 > 锚点 0.490，`ring_islip2d` 0.830 > 0.783。逐链路实测解释了它：

| λ | 接受吞吐 | 最热链路（3,4）利用率 | 全网最大链路利用率 | 若混合比均匀应有 |
|---|---|---|---|---|
| 0.48（稳定） | 0.474 | **0.965** | 0.982 | 0.968 |
| 1.00（过载） | 0.533 | **0.804** | 0.898 | **1.089**（不可能） |

稳定区里接受的混合比就是均匀的（0.965 ≈ 0.968），锚点严格绑定。过载后**逐 VOQ 反压**使 CA 只能授权当前放得下的流，接受的混合比漂离热割 26%（0.804/1.089），于是聚合吞吐反而抬上去。**锚点约束的是稳定区，不是过载峰值**；比较必须用 λ\*，验证清单里也是按 λ\* 断言的（4 项全过）。附带证据：过载时最大链路利用率只有 0.898，说明那时的限制已不是链路而是仲裁器的搜索窗（`ca_probe`/`horizon`）。平均跳数只漂 3.0%（4.53 vs 4.67），所以这是**热割回避**而非「只发近距离包」。

### 8.3 `mesh_base` 的缓冲深度：必须扫，否则把胜负判反

H=7 / V=9 的线延迟使信用往返 ≈ 16～20 拍。CBFC 下每 VC 缓冲小于 RTT 时链路无法连续满载：

| `buf_depth` | 峰值接受 | / 锚点 0.490 |
|---|---|---|
| 4 | **0.078** | 16% |
| 8 | **0.199** | 41% |
| 20（≥ RTT） | **0.396** | 81% |

**5.1× 的跨度。** 只报 `buf_depth=4` 会让集中式看起来赢 6 倍，那是把 CBFC 建错而不是赢了。本报告全部主线数据用 `buf_depth=20`。这同时正是无缓冲 + 集中式方案的卖点：**完全不付 RTT 缓冲税**（`in_network_max` 恒 0，实测两个集中式配置全 λ 点均为 0）。

### 8.4 `conflict_domain` 在稳态口径下是生死线

| fabric | `interval` | `free_at` | 倍数 |
|---|---|---|---|
| mesh | **0.486** | 0.109 | **4.46×** |
| ring | **0.496** | 0.145 | **3.41×** |

批量口径下两者轮次相同（§5-E），稳态口径下差 3.4～4.5 倍。机理是**前沿棘轮**：`free_at` 下刚性传输的起始时刻是路径上各资源前沿的 max，提交后又把**路径上每个**资源推到那个 max——一条拥塞链路把自己的滞后导出给它接触的所有链路，再逐级扩散。`interval` 允许在前沿之前的**空洞**里落座，兑现了 M1「错时穿过同一链路」的自由度。这不是精细化，而是能否工作的差别；代价是仲裁器 6,812 → 103,532 bit（mesh）。

### 8.5 控制环 RTT 的代价只在低载显形

低载 p50（λ=0.01）：`mesh_base` 38 / `mesh_islip2d` 54 / `ring_base` 27 / `ring_islip2d` 46。集中式固定多付 **16～19 拍** ≈ 一个 `T_rtt`，**在 λ < 0.4 区间劣于对应基线**；交叉点就是各自基线的 λ\*（mesh 0.40 / 环 0.55）。这是集中式的真实代价，不该藏起来：**延迟敏感的低载场景不该用集中式 RG。**

## 9. 保序

| 配置 | 机制 | 实测乱序 |
|---|---|---|
| mesh `xy` | M3 同 VOQ 串行 | **0** |
| mesh `romm_static` | M3 + 静态路径 | **0** |
| mesh `romm_dyn` | M3 + **时延不变性** | **0** |
| 环 `fixed` / `balanced` | R5 静态定路 | **0** |
| `ring_base` | 无（偏转 + Swap） | **165 次，重组缓冲峰值 58 flit** |

**一条对计划的修正**：计划预期 `romm_dyn` 乱序 > 0，实测为 **0**。原因是矩形内两段 XY 的跳数恒为 `dx+dy`、线延迟恒为 `dx·H+dy·V`（14,560 组抽样失配 0），所以**换路也不改时延**，M3 的串行足以保序。环上同样地，**最小**候选路径也是时延不变的（2,256 对，跳数与线延迟离散度均为 0），所以 R5 的「必须静态固定」只在允许**非最小**路径时才是必要的（非最小会把 R1 界从 60 反弹到 76，本来就该禁）。**准确表述**：两个 fabric 的保序都由「同 VOQ 串行 + 候选集时延不变」保证，而不是由「路径固定」保证。

## 10. 流水与 `T_rtt` 敏感度

不流水的 makespan ≈ `轮次 × (2·T_rtt + 轮时长)`，会被 FIFO 基线打穿两个数量级。两级流水必须同时成立：数据面轮间按每资源 `free_at` 只等真正复用的资源；控制环按 `pipeline_depth` 信用式重叠。

指标用 `convoy_ratio = convoy_span / data_span`——分子是每轮之间插硬 barrier 的跨度，分母是实际流水跨度，**比值 > 1 即流水仍有收益，= 1 即 RTT 已吃光全部收益**。

| fabric | `pipeline_depth` | T_rtt=8 | 16 | 32 | 48 | 64 | 96 | 临界 `T_rtt` |
|---|---|---|---|---|---|---|---|---|
| mesh | 1 | 1.83 | 1.80 | 1.62 | 1.30 | 1.01 | 0.68 | **65.1** |
| mesh | 2 | 1.84 | 1.83 | 1.80 | 1.74 | 1.63 | 1.32 | > 96 |
| mesh | ∞ | 1.85 | 1.85 | 1.85 | 1.85 | 1.85 | 1.85 | **不敏感** |
| ring | 1 | 1.60 | 1.57 | 1.31 | 0.95 | 0.71 | 0.48 | **45.6** |
| ring | 2 | 1.61 | 1.60 | 1.58 | 1.47 | 1.31 | 0.95 | **91.6** |
| ring | ∞ | 1.61 | 1.61 | 1.61 | 1.61 | 1.61 | 1.61 | **不敏感** |

- **`pipeline_depth=1` 是不可接受的设计点**：mesh 在 `T_rtt ≥ 65`、环在 `T_rtt ≥ 46` 就把全部流水收益还掉。环更早失守，因为它轮次少（69 vs 110），每轮的 RTT 摊销分母小。
- **深度 2 就基本够**：mesh 到 96 拍仍有 1.32× 收益，环推到 91.6。**从 1 到 2 是本研究里性价比最高的单个改动**——一个额外的 outstanding 授权信用，把临界 RTT 从 46 抬到 92。
- 深度 ∞ 完全不敏感，是 RTT 隐藏的上界参考（mesh 1.85 / 环 1.61）。

## 11. mesh vs 环：双口径头对头

**必须双口径。** 环的 96 条无向链路 vs mesh 的 82 条 = **1.17× 金属**，且环继承折叠 torus 的走线（折叠使线长 ×2 ⇒ σ=2）。σ=1 是「同频同宽」口径，σ=2 是「金属恒定」口径。

| 口径 | 指标 | mesh | 环 | 环的优势 |
|---|---|---|---|---|
| σ=1 | 批量轮次（`alltoall`, g=2） | 110 | **69** | **1.59×** |
| σ=1 | 批量数据跨度 | 3880 | **1948** | **1.99×** |
| σ=1 | 稳态 λ\* | 0.48 | **0.75** | **1.56×** |
| σ=1 | 链路下界 | 96 | **60** | 1.60× |
| **σ=2**（金属恒定） | 等效稳态 λ\* | **0.48** | 0.375 | **0.78×（环更差）** |
| σ=2 | 批量轮次 | 113 | 69 | 1.64×（轮次不受 σ 影响） |

**结论对 σ 的取值是敏感的，必须两个都报。** σ=1 下环稳态快 1.56×、批量快 1.59×；一旦按金属恒定折算（环的折叠走线使每跳占 2 拍），环的等效 λ\* 掉到 0.375，**反而比 mesh 差 22%**。所以「2D 无缓冲环优于 2D mesh」只在**允许多付 17% 金属且不折算折叠线长**的前提下成立。批量轮次口径不受 σ 影响（轮次由负载计数决定，§5-G），这也是为什么单看轮次会得到过于乐观的结论。

环真正稳固的优势是别的两条：**低载延迟**（p50 27 vs 38，无缓冲直通 + 平均跳数更短）与**面积**（无 VC 缓冲）。

## 12. 面积与 `T_sched`

单位为 bit（存储与指针状态），门级数为仲裁关键路径的比较器级数估计。

| 配置 | 分布式存储 | 中央仲裁器 | 合计 | 门级 | `T_sched` |
|---|---|---|---|---|---|
| `mesh_base`（VC + CBFC, buf=20） | **616,560** | 0 | 616,560 | — | — |
| `mesh_islip2d`（`free_at`） | 0 | 6,812 | **6,812** | 9 | 110 |
| `mesh_islip2d`（`interval`） | 0 | 103,532 | **103,532** | 13 | 220 |
| `ring_base`（E-tag/I-tag） | **198,528** | 0 | 198,528 | — | — |
| `ring_islip2d`（`free_at`） | 0 | 10,968 | **10,968** | 11 | 69 |
| `ring_islip2d`（`interval`） | 0 | 189,528 | **189,528** | 15 | 138 |

| 对比 | 消掉的存储 | 加回的仲裁器 | 净 | 倍数 |
|---|---|---|---|---|
| `mesh_islip2d` vs `mesh_base` | 616,560 | 103,532 | **−513,028** | **5.96×** |
| `ring_islip2d` vs `ring_base` | 198,528 | 189,528 | **−9,000** | **1.05×** |

两条读法：

- **mesh 侧集中化是明确的面积赢**（5.96×），因为有缓冲 mesh 的 VC 存储本来就是主要成本。
- **环侧几乎面积中性**（1.05×）。`interval` 区间表 184,320 bit 几乎正好吃掉基线省下的 198,528 bit。所以**环上集中化的理由不能是面积，只能是可行性（R4 零松弛）+ 保序 + 稳态吞吐（λ\* 0.75 vs 0.55）+ 公平性**。若面积吃紧，`free_at` 域只要 10,968 bit（18× 更省），代价是稳态吞吐掉到 0.145（§8.4）——这是本研究里最陡的一条面积/性能折中曲线。
- 关键路径：`interval` 比 `free_at` 多 4 个门级（区间表的 AND 树），环比 mesh 多 2 级（多两类端口资源要并入同一个 AND）。

## 14. 已知局限

1. **E-tag/I-tag 的细粒度时序是重建的，不是原文数值。** HPCA'22 *Application Defined On-chip Networks for Heterogeneous Chiplets*（Wang, Feng, Xiang, Li, Xia，海思）原文付费墙，本实现按 HiRD（Hierarchical Rings with Deflection）同源机制与公开阅读笔记重建。`T_inj` / `T_xfer` / `fifo_depth` / `resv_tx` 全部作为**扫参**处理，不声称等于原文配置。基线的绝对数只在本报告内部口径下可比。
2. **维度切片 2D 环下每个节点都是桥（48 个），HiRD 只在少数 bridge router 上设 FIFO。** 这把基线的分布式存储放大了——198,528 bit 中的 49,152（transfer FIFO）+ 12,288（预留 Tx）+ 24,576（Eject Queue）都是逐节点计的。若换成层级环（少数桥），基线面积会显著下降，§12 的 1.05× 会变成集中式吃亏。**这条差异必须随面积数一起引用。**
3. **「集中化消掉了死锁」应收窄为「消掉了为死锁准备的机制」。** §6 实测：本配置下关掉 Swap Rule 也不死锁，因为每节点每环向每拍最多到达 1 个 flit，偏转的续行段总是空的。真死锁需要能阻塞环内 flit 的站点（多 flit 包保持连续、或桥是环层唯一通路），本配置不满足。删掉的是那套机制与它的面积，不是一个已被证实会发生的死锁。
4. **`romm_dyn` 不破坏保序**（实测 0），与计划预期相反；同理环上**最小**候选路径也时延不变，R5 的「静态定路」只在允许非最小路径时才必要。§9 已按实测改写。
5. **BookSim 交叉验证未完成执行。** `anynet` 8×6 拓扑（H=7/V=9）、配置文件与对比脚本 [utils/xval_booksim_8x6.py](utils/xval_booksim_8x6.py) 均已生成，但本环境缺 `flex` / `bison` 且安装需要交互式提权，BookSim 二进制未能编译。故 `mesh_base` 曲线目前只有**内部一致性**（解析锚点 + CBFC 缓冲敏感度 + 拥塞崩溃形态三项定性/定量吻合），缺**外部**交叉验证。这是本报告最大的未闭环项。
6. **过载区峰值接受吞吐不可与解析锚点比较**（§8.2）。混合比会漂离热割 26%。任何引用「峰值吞吐」的结论都必须同时说明该点是否稳定。
7. **σ 口径决定 mesh/环的胜负**（§11）。σ=1 环胜 1.56×，金属恒定 σ=2 环负 22%。单口径结论无效。
8. **`ca_probe` / `horizon` 是仲裁器的搜索预算，会在过载区成为绑定约束**（§8.2 实测过载时最大链路利用率仅 0.898）。本报告未系统扫这两个旋钮，它们对过载区的曲线形状有影响。

## 8. 保序：两个 fabric 的不变量形态不同，但差异不在「环 vs mesh」

保序靠两件事：**M3 / R5 的同 VOQ 串行**（同一 `(s,d)` 的授权 `t0` 全序且占用不重叠）与**时延不变性**（换路不改变到达时刻的相对顺序）。第一件两个 fabric 相同，第二件才是分歧点。

| 路径集合 | 跳数是否随候选变化 | 线延迟离散的对数 | 最大离散 | 是否时延不变 |
|---|---|---|---|---|
| mesh XY（唯一路径） | — | — | — | 是（平凡） |
| mesh ROMM（矩形内中间点） | 否（恒为 dx+dy） | **0 / 14,560** | **0** | **是** |
| 环最小候选（方向 × 维序，每相取最短方向） | 否（恒为环距 dx′+dy′） | **0 / 2,256** | **0** | **是** |
| 环全候选（允许绕远方向） | 是 | **2,112 / 2,256（93.6%）** | **78 拍** | **否** |

**⚠ 这里推翻了计划的一条论断。** 计划说「环上候选路径时延**不同** ⇒ 必须静态定路（R5）」，把它作为环与 mesh 的**结构性差异**。实测不是：环的**最小**候选集与 mesh ROMM 一样时延不变（2,256 对全部 0 离散），因为两相的跳数恒等于环距之和、线延迟恒等于 `dx′·H + dy′·V`，与方向和维序都无关。

真正的界限不在 fabric，而在**是否允许非最小路径**：一旦放开绕远方向，93.6% 的对出现时延离散、最大 78 拍，换路必然乱序。所以 R5 的「静态定路」应当重述为：

> R5 的路径固定要求，是**允许非最小路径时**才必需的；在最小候选集内，环与 mesh 一样可以动态换路而不破坏序。

这对算法有实际后果：`ring_path_mode=balanced` 的离线平衡（把下界从 60 压到 49）**只在最小候选集内选择**，因此它既拿到了负载均衡又不需要放弃动态性——它静态固定是为了可复现，不是为了保序。而放开到非最小路径同时是**有害的**（下界从 60 反弹）**且不保序**，两个理由都指向不做。

## 9. 流水与 `T_rtt` 敏感度

轮次 69～110，若每轮都要等一个全局 barrier，makespan ≈ `轮次 × (2·T_rtt + 轮时长)`，会被 FIFO 基线打穿。两级流水必须同时成立：

- **数据面轮间流水**：每资源记 `free_at` / 区间表，相邻轮只等真正复用的资源。对照量是 `convoy_span`（硬 barrier 口径）：mesh 7097 vs 数据跨度 3880 = **1.83×**，环 3125 vs 1948 = **1.60×**。这就是「不做轮间流水」的代价。
- **控制环流水**：信用式，深度 `pipeline_depth`，源不等数据发完就发下轮 request。

**`convoy_span / data_span` 随 `T_rtt` 的衰减，交叉点 = 流水收益被 RTT 吃光的临界 RTT**（比值 ≤ 1 意味着流水已不如硬 barrier）：

| `T_rtt` | mesh d=1 | mesh d=2 | mesh d=∞ | 环 d=1 | 环 d=2 | 环 d=∞ |
|---|---|---|---|---|---|---|
| 8 | 1.83 | 1.84 | 1.85 | 1.60 | 1.61 | 1.61 |
| 16 | 1.80 | 1.83 | 1.85 | 1.57 | 1.60 | 1.61 |
| 32 | 1.62 | 1.80 | 1.85 | 1.31 | 1.58 | 1.61 |
| 48 | 1.30 | 1.74 | 1.85 | 0.95 | 1.47 | 1.61 |
| 64 | 1.01 | 1.63 | 1.85 | 0.71 | 1.31 | 1.61 |
| 96 | 0.68 | 1.32 | 1.85 | 0.48 | 0.95 | 1.61 |
| **临界 `T_rtt`** | **65.1** | 无（>96） | **无** | **45.6** | **91.6** | **无** |

三条结论：

1. **环比 mesh 对 RTT 更敏感**（临界 45.6 vs 65.1）。不是环的控制面更差，而是它的数据跨度只有 mesh 的一半（1948 vs 3880），同样的 `T_rtt` 占比翻倍。**性能越好的 fabric，对控制时延越敏感**——这条在设计控制面 NoC 时比绝对数值更有用。
2. **深度 2 就够**：`pipeline_depth=2` 把 mesh 的临界 RTT 推到 >96、环推到 91.6。从 1 到 2 的收益远大于从 2 到 ∞。
3. **深度 ∞ 时 RTT 完全消失在比值里**（恒 1.85 / 1.61），因为 RTT 只贡献一次性的管线填充 `+T_rtt`，不再乘轮次。

## 12. 面积与 `T_sched`：集中化在 mesh 上省，在环上打平

单位是**存储比特**（`utils/rg_sched_cost.py`，`W_FLIT=128`）。分布式侧按每节点/每桥实例化后求和，集中侧是一份仲裁器。

**分布式基线消掉的部分**

| 配置 | 项 | bit |
|---|---|---|
| `mesh_base` | 输入缓冲（48 节点 × 5 端口 × 2 VC × `buf_depth=20` × 128 bit 的等效） | 614,400 |
| | 信用计数器 | 1,440 |
| | 交换分配器指针 | 720 |
| | **合计** | **616,560** |
| `ring_base` | 桥 transfer FIFO（48 桥 × 2 环向） | 49,152 |
| | 预留 Tx buffer | 12,288 |
| | Eject 队列 | 24,576 |
| | 目的端重组缓冲（峰值实测 58 flit，按 16 定尺寸 × 48） | 98,304 |
| | Swap bypass 通路 | 12,288 |
| | 饿死阈值计数器 + I/E-tag 状态 | 1,920 |
| | **合计** | **198,528** |

**集中式仲裁器的成本**

| | 残余位图 | 指针 | 弧表/端口计数 | `free_at` | 区间表 | 合计 | 门级深度 | `T_sched` |
|---|---|---|---|---|---|---|---|---|
| mesh `free_at` | 2,256 | 1,272 | — | 3,120 | — | **6,812** | 9 | 110 |
| mesh `interval` | 2,256 | 1,272 | — | — | 99,840 | **103,532** | 13 | 220 |
| 环 `free_at` | 2,256 | 456 | 2,496 | 5,760 | — | **10,968** | 11 | 69 |
| 环 `interval` | 2,256 | 456 | 2,496 | — | 184,320 | **189,528** | 15 | 138 |

**净账**

| 对照 | 消掉 | 新增（区间域） | 净 | 比值 |
|---|---|---|---|---|
| `mesh_islip2d` vs `mesh_base` | 616,560 | 103,532 | **−513,028** | **5.96×** |
| `ring_islip2d` vs `ring_base` | 198,528 | 189,528 | **−9,000** | **1.05×** |

三条要点：

1. **区间表是集中式面积的全部**（mesh 99,840/103,532 = 96%，环 184,320/189,528 = 97%）。用 `free_at` 域面积会掉到 6,812 / 10,968 bit——**15～17× 更便宜**，但稳态吞吐掉到 1/3～1/4（§10）。这是本研究里最陡的一条面积-性能权衡，且**没有中间选项被测过**（滑动窗宽度是显然的旋钮，未扫，列入局限）。
2. **mesh 侧的 5.96× 几乎全部来自「不付 RTT 缓冲税」**：`mesh_base` 的 614,400 bit 输入缓冲是按信用往返（≈2×(7\~9) 拍）定尺寸的，而这个尺寸由**线延迟**决定，不由流量决定。集中式无缓冲方案根本没有这一项。
3. **环侧打平**是因为基线本来就没多少缓冲（198,528 vs mesh 的 616,560，3.1× 更少），而集中式的区间表尺寸与 fabric 的资源数成正比——环有 192 条链路 + 96 个端口，比 mesh 的 164 条链路**更多**，所以区间表反而更大。**资源越多的 fabric，集中化的面积回报越差**，这条与直觉相反。

`T_sched` 是**排程轮次**（每轮一次匹配），不是拍数：mesh 110 / 环 69（`free_at`），区间域因为要做位图 AND 而门级深度从 9/11 涨到 13/15。区间域的 `T_sched` 列出的 220/138 是「若每轮需两个仲裁周期」的保守口径。

## 13. 验证清单（`utils/verify_islip2d_8x6.py`，49/49 通过）

每一项都是可执行断言，失败时打印具体量而非只报 fail。产物 `results/verify_islip2d_8x6.json`。

**通用（9 项）**：mesh / 环逐资源两两复核 **0 冲突**；mesh 轮内两两复核 overlaps=0 且 ramp 违例=0；轮次 ≥ 下界（mesh 110 ≥ 96、环 69 ≥ 60）；残余位图纪律逐轮集合恒等；控制面每轮 **82.3 条**（上界 96）对照一次性汇聚 4,512 条；环转环驻留 **max=0**（兑现无缓冲）。

**D-M 专项（7 项）**：割界 = **96** 并给出见证（`x=4` 东向，576 条流 / 6 条链路）；XY 实测峰值负载 = 96 = 割界；ROMM 时延不变性 **14,560 组失配 0**；「无余量则 ROMM 无负载增益」**零反例**；`permutation` 的轮次增益被单独识别为**打包效应**而非负载效应；`xy` / `romm_static` / `romm_dyn` 乱序率**全为 0**（ROMM 动态换路也保序，因时延不变）。

**D-R 专项（11 项）**：192 有向 / 96 无向链路；金属比 **1.1707×**；**链路集与折叠 2D torus 逐条相同**（only_mine=0, only_torus=0，证明差别只在节点）；每节点皆桥（48）；R1 界 60（`fixed`）/ 49（`balanced`）；最小候选**时延不变**（2,256 组，离散 0）；纯链路判据**不安全率 1.08%** 与类型分布；并发度高估 **1.52×**；`whole_ring` **2.83×**；五子句在 `ports=1` 与 `ports=2` 下逐条 0 违例。

**`ring_base` 专项（6 项）**：固定维序下 Swap Rule **0 次触发**且仿真正常完成；`mixed` 维序下**触发 74 次**；**关掉 Swap 也不死锁**（时隙稀缺与流水两种模式都完成，并标注「偏离计划」）；环内 flit **从不被阻塞**（4 种配置全 0）；饿死有界（`T_inj` 8/16/64 → 119/56/112 拍）；偏转造成乱序 165 次、重组峰值 58 flit。

**稳态专项（14 项）**：四配置 λ\* 全部 ≤ 解析锚点（0.40/0.45 ≤ 0.49，0.55/0.75 ≤ 0.783）；两个集中式配置**网络内驻留恒 0**；缓冲深度必须覆盖 RTT（峰值 0.0776 / 0.1991 / 0.3962）；饱和后**接受吞吐不再上升**（`mesh_base` 回落 0.108、`ring_base` 回落 0.023、两个集中式回落 **0**）；`interval` 相对 `free_at` **4.46× / 3.41×**；低载 RTT 代价（p50 集中式 54/46 vs 基线 38/27）。

**关于「λ\* ≤ 锚点」这条检查的口径**：`peak_accepted` 可以**超过**锚点（mesh 0.525 > 0.49），这不是 bug。锚点是均匀全互联流量下最热链路的界；一旦过载，逐 VOQ 反压使**被接受的流量组成偏离均匀**，避开热割。实测：λ=0.48（稳定）时最热链路利用率 0.965，与均匀预测 0.968 一致；λ=1.0 时降到 0.804，而均匀预测本应是 1.089（不可能）——组成偏离了 26%。而平均跳数只变了 3%（4.65→4.53），所以**必须看割上的负载而不是跳数**才能看清这个偏移。因此断言写在 λ\*（稳定区上界）上，不写在峰值上。

## 14. 已知局限

1. **`ring_base` 的 E-tag/I-tag 是重建，不是复刻。** HPCA'22 *Application Defined On-chip Networks for Heterogeneous Chiplets*（Wang 等，海思）原文付费墙，细粒度时序按 HiRD（Ausavarungnirun/Fallin/Mutlu）同源机制与公开阅读笔记重建。`T_inj` / `T_xfer` / `fifo_depth` / `resv_tx` / `reasm_depth` 都是**扫参**，不是原文数值。故基线的绝对曲线位置有不确定性；相对结论（偏转消耗带宽、乱序需重组缓冲、无死锁）依赖的是机制而非具体阈值。
2. **每节点皆桥放大了基线开销。** 维度切片 2D 环下 48 个节点全是行/列环之间的桥（已断言），而 HiRD 只在少数 bridge router 上放 FIFO。所以 `ring_base` 的 198,528 bit 是**本拓扑下**的账，不能直接引用为 HiRD 的开销。若改成分层环（少数桥），基线面积会大幅下降，而 §12 的「环上打平」会变成「环上集中化更贵」。
3. **「关 Swap 必现死锁」没能复现，所以「集中化消掉死锁」是消掉机制而非消掉已证实的故障。** 已在 §6 收窄。要建出真死锁需要能**阻塞环内 flit** 的站点（多 flit 包保持连续、或桥是环层间唯一通路），本模型两者都不满足。这是本研究最大的未闭合项。
4. **区间表的窗宽没有扫。** `interval` 用固定 `span` 的滑动位图，面积占集中式的 96%/97%。窗宽是显然的面积-性能旋钮（更窄 → 更便宜但回填机会更少），介于 `free_at`（窗宽 1）与当前配置之间的中间点**一个都没测**。
5. **BookSim 交叉验证未能执行。** `utils/xval_booksim_8x6.py` 已就绪（生成 8×6 `anynet` 拓扑文件、H=7/V=9 链路时延、多个负载点与缓冲深度的配置，并与 `run_steady` 逐点对比），但本环境缺 `flex` / `bison` 且安装需要交互式提权，BookSim 无法编译。故 `mesh_base` 只与解析锚点对照，未与独立实现对照。这是**基线可信度的主要缺口**——若 `mesh_base` 的 CBFC 建模偏悲观，§12 的 5.96× 面积优势会缩小。
6. **理想化 1 拍控制消息。** 按既定口径，request / grant 的传输本身不占带宽、不排队，只付常数 `T_rtt`。真实控制面 NoC 的拥塞未建模；每轮 82.3 条消息的可行性依赖一套独立控制网络的存在，其面积**未计入** §12。
7. **`m` 与 `σ` 只扫到 {1,4,16} 与 {1,2}。** 轮次对 `m` 完全不敏感（负载计数决定），但稳态的多 flit 包在 `interval` 域下触发了 `avail_run` 的量词顺序问题（已修，见 §1）；更长的包（m ≥ 32）与 σ ≥ 4 未测。
8. **流量只覆盖 alltoall 与 7 个 any-to-any pattern。** 突发性（burstiness）、局部性（邻近通信占比）、混合包长都未扫。稳态扫描全部是 Bernoulli 到达 + 均匀目的。
